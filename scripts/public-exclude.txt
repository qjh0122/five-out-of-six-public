# 导出到公开库时整块剔除的路径 —— 唯一事实来源
#
# 谁在读这份清单：
#   ① scripts/publish-public.sh —— 导出后按本清单逐条删除
#   ② scripts/check-docs.js    —— 公库上把这些路径下的链接从「死链」里豁免
#
# 为什么必须只有一份：2026-11-22 之前剔除写死在发布脚本里、死链检查写死在
# docs 守里，两边各记一份。导出时删掉了 docs/review，守却仍要求 INDEX 里
# 指向它的链接必须存在 —— 公库 CI 从 11-18 起每次必红，19 条死链，
# 而私库全绿。不是谁写错了，是**同一个事实被抄了两份**。
#
# 格式：每行一个仓库相对路径。
#   · 以 / 结尾表示目录
#   · 支持 * 通配（只匹配单层，不跨 /）
#   · # 开头为注释行，空行忽略
#
# 豁免判据（重要）：只有当某一条在本机**整体不存在**时，才认作「已按公开库剔除」，
# 其下的链接才不计死链。条目存在就不豁免 —— 所以私库里 docs/review 在，
# INDEX 写错一个文件名照样会红。豁免不是「文件不在就放过」的后门。

# 指定头像：真实玩家的照片，公开仓库绝不能有。
# 代码保留（avatar.js 的 CUSTOM 表只有 playerId → 文件名，不含昵称），sw.js 的
# PRECACHE 条目也保留 —— install 是逐条容错的（add().catch()），缺图只会少缓存几张。
# 公库本身不部署，这几条 404 不影响任何线上环境。
pwa/assets/avatar-custom/

# 成就评估报告：逐个玩家的解锁进度（昵称 + ID + 分数），属于玩家数据。
docs/achievements-review-*.md

# 发布脚本自身：下面的脱敏表就写着「哪些串是真实昵称」，公开它等于公开清单；
# 公库读者也不需要「怎么把私库同步到公库」这套运营工具，它还带着内部路径。
scripts/publish-public.sh
