## 三、问题清单（按玩家困惑程度降序）

### P0 — 会直接导致误解

**1.【真问题·高】回放入口与弹窗标题两个名字**
- 原文：`pwa/index.html:536` `<button id="btn-replay" …>本局过程</button>`
- 原文：`pwa/index.html:569` `<h2 id="replay-title">本场过程</h2>`
- 措辞在 `recordsView.js:129` 又变成「这一场的牌面过程」。
- 玩家困惑：点「本局过程」弹出「本场过程」，会怀疑是不是点错/看错了另一局。
- **建议**：统一为「本局过程」（改标题，不动按钮，风险最小）；如产品定义「场」才是正式量词，则两处一并改「本场过程」。

**2.【真问题·高】量词「场 / 局」在同一战绩页内混用**
- 原文：`index.html:728`「共 0 局」；`:713`「最近 10 场」；`:697`「单场最高」；`:702/706`「最长连胜/连败 N 场」；`:668`「N 场」。
- 原文：`game.js:3642`「这一把你不打」vs `:1073`「这一局你在旁边看」。
- 玩家困惑：同一页里「场」和「局」交替出现，无法判断是不是两种不同统计口径；结合「把」共三个量词，玩家很难确定「打几把」和「打了多少场」的关系。
- **建议**：定一条量词契约并全站执行——「把」= 单次发牌（含两轮，保留 `index.html:1117`「一把两轮」），「局」= 建房到结束的一整场（把「最近 10 场」「单场最高」「最长连胜 N 场」「共 0 局」统一到同一量词）。`admin.html:799/803` 已明确区分「场/把」，可作为契约样板。

**3.【真问题·高】错误文案禁用词违规**
- 规格：`docs/design-states-v1.md:129`「禁用词（出现在任何玩家可见位置都算施工不合格）：操作失败 / 请稍后重试 / 网络异常 / 请求失败 / 系统繁忙 / 错误码 1023」。
- 原文：`game.js:411` `var msg = (res && res.error) || '操作失败';`（`flashRoomError` 全站房间操作兜底，`:1027/:3641/:3661` 亦有同字符串）
- 原文：`game.js:4939` `'网络异常，稍后再试。'`（成就页加载失败）
- 原文：`admin.html:504` `'网络异常，请检查连接后重试'`（后台，玩家不可见，优先级低）
- **建议**：按 `design-states-v1.md §②-b` 文案表改为具体动作提示；`flashRoomError` 的兜底至少改为「这步没成功，房间没变化，再点一次」一类说明后果的话，不用禁用词。

**4.【真问题·高】净胜 / 净得分裂**
- 原文：`index.html:954` + `settleView.js:592`「本轮各家净得」（运行时由 JS 覆写为同一文本，属同一处）。
- 对照：`settleView.js:934`「净胜 = 最终分 − 初始 N 分」、`index.html:665`「累计净胜」、`recordsView.js:849/963`「累计净胜/我的净胜」。
- 玩家困惑：结算弹窗说「净得」，弹窗关闭后尾注和战绩页都说「净胜」，会以为是两种算法。
- **建议**：改为「本轮各家净胜」。

### P1 — 明显不一致但不太会误判

**5.【真问题·中】战绩 / 记录混用**
- 原文：`index.html:815` 按钮「清除记录」；`:889` 标题「清除全部战绩？」；`:896`「当前 0 场记录将被删除」；`recordsView.js:897`「暂无战绩记录」；`recordsState.js:68`「可显示的战绩」/`:71`「这台设备上的记录」。
- **建议**：全站统一「战绩」；需要区分本机副本时写「本机战绩」，不要在同一句里「战绩/记录」互换。`recordsView.js:1848` 同一分支的两种回执（「战绩已清除」/「已清除这台设备上的记录」）同样处理。

**6.【真问题·中】开局动作四个动词**
- 原文：`game.js:742`「还差 N 人才能开局」/`:746`「全部准备好，马上开始」/`:3662`「已放行，人齐就开牌」；`nextRoundHints.js:97`「点「开始下一局」就开」；`index.html:529` aria-label「先别开牌，我等个人」。
- **建议**：状态提示统一「开局」，主按钮保留「开始下一局」，「等人」按钮的可见文字/aria-label 统一到「开牌」或统一到「开局」，二选一。

**7.【真问题·中】「出了点问题」万能文案**
- 原文：`game.js:389`「出了点问题，已经记下了」；`:2896`「交牌出了点问题，已经记下了」；`:3542`「进房出了点问题，已经记下了」。
- 说明：有 ErrorReport 上报 + 「已经记下了」比纯「操作失败」好，但都没有告诉玩家「刚才那一步算不算数、战绩有没有丢」「现在能不能再点一次」。另 `game.js:2306/3682`「撤回不了，稍后再试」、`:3569`「暂时进不去，稍后再试」属同类无按钮、无具体动词的泛化重试提示，与 `design-states-v1.md:134-136`「可重试类一律用具体动词」相悖。

## 四、取证限制（如实标注）

1. **纯静态审查**：未启动浏览器、未跑真机探针、未取得实际渲染帧。因此「文案是否在屏幕上换行成歧义」「读屏软件是否真的念出 aria-label」无法验证；标【存疑需看图】的三项须由持有截图/真机的同事复核。
2. **字符串提取的边界**：采用「引号内含汉字」正则，可覆盖单引号、双引号、模板串中的字面量，但**动态拼接出来的句子**（如 `game.js` 中由多段变量拼成的提示）只能按片段取证；代码注释中的同类措辞已人工剔除，不计为玩家可见文案。
3. **未做运行时可达性验证**：例如 `index.html:954` 的静态「本轮各家净得」与 `settleView.js:592` 的覆写文本一致，是通过读两处源码确认的，不是运行后抓屏确认的。若某条文案实际被更上层的分支覆盖，结论需修正。
