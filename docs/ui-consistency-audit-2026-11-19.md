## 〇、一句话结论

**这套 UI 的问题不在"没有规范"，而在"规范只覆盖了它想得到的形状"。**
B1/B2/B3 的骨架（token、动效、四态、数字阶梯）全部守住且测试全绿，但三域各自独立地撞见同一种病——
守卫只查它写得出来的那一层，于是"测试全绿、玩家仍看得到两套答案"。

最典型的四例：
- 结算冠军净胜，**同屏两个值**：冠军块 30px 金色、名次表 48px 涨跌色（`style.css:3256` vs `:3203`）；
- `--text-main` **4 处引用 0 处定义**，颜色靠 `body` 继承的偶然结果在显示；
- "外投影字面量 == 0" 只在分类器"只看第 1 层"的定义下成立，**9 处裸投影藏在第 2/3 层**（含 1 处 JS 内联）；
- 点"本局过程"按钮，弹出标题写着"本场过程"的弹窗（`index.html:536` vs `:569`）。

按玩家可感知度排序，真正值得动手的 **P0 共 8 项、P1 共 9 项**，全部是局部改动，无一项需要重做体系。

## 二、P1 · 明显不一致，建议排期

**视觉域**
- P6：结算页同屏 9 档字号，16/22/30/40 在六档阶梯外，文字层没收敛（`style.css:3255` 等）。
- P7：圆角 21 档无 token，11/12、26/28 的 1~2px 近重复漂移（`style.css:2909/970` 等）。

**交互域**
- P2：确认框无严重度分级——删号与"每把都点"共用同一张红实心"确定"，只靠多出的密码框区分（`game.js:2836`/`accountView.js:508`/`index.html:1170`）。danger 变体现有却只用在入口没用在确认键。建议 `askConfirm` 加 `opts.tone`。
- P3：删号密码框不支持 Enter，与其余 5 个输入框不一致（`game.js:3087-3096`）。
- P4：首页昵称框 Enter 直接建房，但输入框旁没有提示（`game.js:5118-5120`）。建议 placeholder 加"（回车创建房间）"或 Enter 只 blur。
- P5：忙碌态两套视觉——确认框只换文字不转圈；两个加载环周期不同（0.7s / 900ms，`style.css:478`/`records.css:609`）。
- P6：结算页 3 颗次级按钮裸用 `.btn`，与相邻 ghost 按钮皮肤不同（`index.html:535/536/539` vs `:546/547`）；`style.css:444` 注释已过期。

**文案域**
- P5：战绩/记录混用（"清除记录"按钮 vs"清除全部战绩？"标题，同句"暂无战绩记录"）。
- P6：开局动作四个动词（开局/开牌/开始/开）。
- P7："出了点问题"万能文案 + 无具体动词的"稍后再试"（`game.js:389/2896/3542/2306/3569`）。
- P8：AI 三个叫法（AI 队友 / AI 玩家 / 含人机）。
- P10：成就文案中文数字"十场/十五场"与全站阿拉伯数字不一致（`achievements.js:582/585/609`）。
- P11：`aria-label="纪录"` 用字不一致、房间号 placeholder "6位" vs aria-label "6 位"（`index.html:695/363`）。

## 三、真浏览器取证据（制作人亲跑，静态审查看不到）

`ONLY="iOS竖390×844" node scripts/probe-ui-flow.js` 与 `ONLY="iOS横844×390" node scripts/probe-ui-flow.js`：

- **两档 × 13 屏均 ALL PASS**：无出界、无溢出、无遮挡、无截断、无 <30px 硬热区。
- **2 条"半行硬切"**（软问题，滚动一下能看到）：结算 `div.settle-inner` 只露出 91%、完整规则 `dl.rules-list` 只露出 82%（仅竖屏）。→ 建议 P1 排期时顺手确认是否为有意的滚动区。

这条证据给三域报告补上了"没开浏览器"的缺口：静态推断的遮挡/热区硬问题在现网并不存在。

## 四、制作人裁定（子报告请我拍板的两点）

1. **禁用词口径（文案 P3 是否降级）**：**不降级，维持 P0**。规格 `design-states-v1.md:129` 原文"任何玩家可见位置都算施工不合格"，`design-states-v2.md:85` 明确"§② 全部沿用、禁用词未改判"，且 v1 §② 是 v2 作废后唯一保留的封存引用。口径是全域的。
   - 但如实记账一处规格张力：`qa-states-v1.md:65/114` 把禁用词命中检查限定在 L2（不可恢复类）可见文案。汇编采用更严格的"任何玩家可见位置"，因为文字本身（"操作失败"把责任推给玩家）不因错误分级而改变不当性。
2. **美术推翻旧审计"负分统一改亮绿"的 P0 建议**：**采纳美术判断，不执行那条旧建议**。两套涨跌色是按底色切换的色阶（浅底用深绿保 4.5:1），有注释和 `prev-result.test.js` 守卫；统一成亮绿会破坏对比度。这是审查该有的独立复核——旧结论不因写在文档里就免于被推翻。
