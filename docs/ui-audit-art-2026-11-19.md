## 三、问题清单（按玩家可感知程度排序）

### P1 · 结算页"冠军净胜"同一数字，两处字号与颜色都不同
- **证据**：`style.css:3203` `.settle-row.champion .settle-net { font-size: var(--num-2); }` = **48px**，色随涨跌（`--up-red`/`--down-green`，`style.css:3200-3201`）；`style.css:3256` `.sc-net { font-size: 30px; color: var(--gold); }` = **30px 金色**。二者渲染的是同一个数：`settleView.js:674` `el('p','sc-net', (top.score>0?'+':'')+top.score+' 分')` 与 `settleView.js:803-804` 的 `.settle-net`。
- **为何是真问题**：每局结算必现。顶部冠军块写"冠军 +15 分"（30px 金），下面名次表冠军行写同一个 +15（48px 红/绿）。玩家被要求把两个不同大小、不同颜色的数字读成同一件事。更糟的是层级方向相反：冠军块里名字 40px > 净胜 30px（`style.css:3255`），名次表里名字 28px < 净胜 48px（`style.css:3194/3203`）——"数字是主角"这条设计原则在同一屏自相矛盾。
- **为何守卫没抓到**：`number-scale.test.js:76-95` 的 `NUMERIC_SELECTORS` 白名单收录了 `.settle-net`，**没有 `.sc-net`**；`[3]` 节只检查 `.settle-row.champion .settle-net`。`30px` 也落在 `:root` 六档之外。
- **建议改法（不动手）**：把 `.sc-net` 纳入数值白名单并改走 `var(--num-2)`，与名次表冠军同档；名字 `.sc-name` 的 40px 降为 `var(--num-2)` 或 `var(--num-3)`，使冠军块与名次表保持"净胜 ≥ 名字"的一致层级。颜色若需保留金（冠军荣誉语义），则名次表冠军也应有同一层金色标识，而不是涨跌色——二选一，不要两套。改完补一条断言：`.sc-net` 的 computed font-size 必须等于 `.settle-row.champion .settle-net`。
- **复跑**：`grep -n '\.sc-net\|\.settle-row.champion \.settle-net' pwa/css/style.css`

### P2 · 8 处黑色裸外投影藏在组合声明第 2 层，测试声称"手写外投影=0"实测不成立
- **证据**：`design-tokens.test.js:86-99` 的 `isElevation()` 只取 `layers(v)[0]` 判断，第 2 层及以后完全不看。以下 8 处第 2/3 层是裸写黑色外投影（模糊值 14/18/18/22/24/30/40/46px，全部不属于三档 6/22/56）：

  | 位置 | 漏检的第 2 层 | 与三档的关系 |
  |---|---|---|
  | `style.css:639` | `0 8px 18px rgba(0,0,0,0.16)` | 18 ≈ 22 但不等 |
  | `style.css:975` | `0 18px 40px rgba(0,0,0,0.28)` | 40 介于 22 与 56 |
  | `style.css:1303` | `0 18px 46px rgba(0,0,0,0.34)`（第3层） | 46 介于 22 与 56 |
  | `style.css:1733` | `0 10px 22px rgba(0,0,0,0.20)` | 模糊=22 但透明度≠0.34 |
  | `style.css:1739` | `0 10px 24px rgba(0,0,0,0.4)` | 24 ≈ 22 |
  | `style.css:2141` | `0 6px 14px rgba(0,0,0,0.16)` | 14 介于 6 与 22 |
  | `style.css:3455` | `0 12px 30px rgba(0,0,0,0.42)` | 30 介于 22 与 56 |
  | `style.css:4876` | `0 6px 18px rgba(15,43,34,0.22)` | 18，且带墨绿色相 |

- **为何是真问题**：这正是旧审计 B1 要消灭的"71 个光源"的残骸——8 个介于三档之间的高度，玩家看到部分卡片/行"浮"得比邻座高一点或低一点，读不出统一层级。
- **为何是守卫盲区**：`isElevation()` 的注释（`design-tokens.test.js:83-84`）明确写了"只看第一层"，并把它当成**特性**（`0 0 16px 光环, var(--elev-2)` 应放行）。这个判断对"光环+已归位高度"是对的，但副作用是"inset 描边 + 裸投影""状态环 + 裸投影"两类组合全部放行——旧审计 §B1 实施记录里踩过的 `split(',')` 分类器 bug 换了个形态重演。
- **建议改法（不动手）**：把 8 处逐一收敛到 `--elev-1/2/3`（按模糊值就近取档：14/18→elev-1、22/24/30→elev-2、40/46→elev-3），保留其原有的 inset 边或状态环在前。同步把 `isElevation()` 改为**逐层判定**：任一层命中外投影特征即判违规，同时对"光环 + var(--elev-*)"这种已归位组合显式放行（白名单要写进注释，不能靠"只看第一层"蒙混）。补变异自证：塞一条 `inset …, 0 10px 24px rgba(...)` 必须红。
- **复跑命令**（本次实际使用，可直接复制）：

### P3 · JS 内联样式里还有 1 处完全脱离 CSS 约束的裸外投影
- **证据**：`cardView.js:199` `z-index:40;pointer-events:none;border-radius:16px;box-shadow:0 16px 32px rgba(0,0,0,0.45)`——模糊 32px、透明度 0.45，与三档（6/22/56）均不符。
- **为何是真问题**：`design-tokens.test.js:27-28` 的 `FILES` 只列 4 个 CSS 文件，**JS 生成的 inline style 一律不扫**。这是"测试全绿"最彻底的盲区：连分类器都不用骗，它根本没被读。
- **建议改法（不动手）**：改为 `box-shadow:var(--elev-2)`（32 介于 22 与 56，按"离桌面多高"取档），或把这个浮层收成 `.modal-box` 的既有类；守卫增加一条"JS 内联样式禁止出现 `box-shadow:\s*0`"的静态断言。
- **复跑**：`grep -rn 'box-shadow' pwa/js/cardView.js pwa/js/settleView.js pwa/js/seatRing.js pwa/js/bestLine.js pwa/js/recordsView.js`

### P4 · `--text-main`：4 处引用、0 处定义，颜色声明静默作废
- **证据**：`style.css:1000`（`.tr-v`）、`3255`（`.sc-name`）、`3322`（`.sp-title`）、`3352`（`.shl-opt`）使用 `color: var(--text-main)`；全项目无 `--text-main:` 定义，JS 也无 `setProperty('--text-main', …)`，`index.html` 无内联定义。
- **为何是真问题**：CSS 自定义属性未定义且无 fallback → 声明在 computed-value 时作废，`color` 回退到 `inherit`。当前祖先 `body { color: #f5f0e6 }`（`style.css:126`），所以恰好渲染成暖白、恰好可读——**这是继承的偶然结果，不是设计**。一旦祖先颜色调整，结算冠军名字、旁听标题、结算页"下一把打几把"选项会一起变色且无任何测试报警。这是旧审计 B2 亲手抓过的"`var(--dur-9)` 写错名字静默作废"的同型缺陷，换到了颜色域，且颜色域根本没有引用完整性守卫（判据 3/4 至今未做）。
- **建议改法（不动手）**：在 `:root` 明确定义 `--text-main`（语义是深底主文字，值应等于现网实际继承到的暖白），或四处分别改用已有的 `--warm-white` / `--text-secondary`。补一条通用断言：所有 `var(--x)` 引用必须能解析到 CSS 定义或 JS `setProperty` 白名单（JS 注入项如 `--vp-h`/`--slot-color`/`--tail-off` 等在 `design-tokens.test.js` 里显式列出）。
- **复跑**：
  ```bash
  comm -23 <(grep -oh 'var(--[a-z0-9-]*' pwa/css/*.css | sed 's/var(//' | sort -u) \
           <(grep -oh -- '--[a-z0-9-]*:' pwa/css/*.css | sed 's/://' | sort -u)
  # 输出里的 --text-main 即本问题；其余 --vp-h/--ls-scale/--slot-color/--tail-off 等为 JS 注入，合法
  grep -rn -- '--text-main' pwa/
  ```

### P5 · JS / Canvas 侧颜色是 token 的硬编码副本，改 token 不会同步
- **证据**：`recordsView.js:934-1010`（战绩分享图 Canvas）：`#1E5A44`=`--green-bright`、`#F5C15C`=`--gold`、`#FF5D5D`=`--up-red`、`#3DDC84`=`--down-green`、`#FFF7E8`=`--warm-white`，全部写死；`cardView.js:51-54/83-87`、`settleView.js:108-110` 另有 11 个全新色（`#3D7EA6`/`#B8862B`/`#8B5CC7` 等）不在 `:root`。
- **为何是真问题**：同一份战绩在屏幕上是 token 色、导出成图后是硬编码色。目前数值巧合相同所以看不出，但它使"改一处色板、全站同源"这件事在分享图上永久失效——这正是"同一双手"最容易被打破的地方。`cardView.js:79-80` 的注释证明作者是有意识调色的（浅底另选 `#FFD978`），所以**不是随手乱写**，但调色结果没有回写进 token 体系。
- **建议改法（不动手）**：短期在测试里钉死"Canvas 常量必须与 :root 对应 token 值相等"，把 JS 色值纳入 token 单一来源的校验；中期让 Canvas 通过 `getComputedStyle(document.documentElement).getPropertyValue('--up-red')` 读 token，或把牌型特效色补成一组 `--fx-*` token。
- **复跑**：`grep -n '#[0-9a-fA-F]\{6\}\|rgba(' pwa/js/recordsView.js pwa/js/cardView.js pwa/js/settleView.js`

### P6 · 同屏文字层仍有 4 档在数字阶梯之外
- **证据**：结算页 `.settle-recheck`(24) / `.sr-hint`(22) / `.sc-name`(40，梯外) / `.sc-net`(30，梯外) / `.settle-tip`(20) / `.settle-ai-note`(20) / `.settle-reset-note`(20) 同屏并存；v150 实测 `#settle-body` 40 个叶子节点用了 9 档，其中 16/22/30/40 共 17 个节点在梯外。本次复测纯数值档仍是 28 档（含 15/17/19/21/26/27/34/36/38/42），**v150 之后没有收敛**。
- **为何是真问题**：数字层（六档）收敛了，承载数字的文字层没收。`--num-*` 的注释（`style.css:80-82`）说"数值元素只能落在这四个之一"，但同样在读数的说明文字可以在 20/22/24/30 里任选，于是一屏出现"9 档字号、重心散"。
- **建议改法（不动手）**：把 22/30 并到既有单位档 `{20,28}`，40 并到 `--num-2`（48）或 32；为文字层补一条比 numeric 更宽的阶梯 `{20,24,28,32}`，并把 `--dur-*`/`--ease-*` 的"想加档先改文档"纪律套用到字号。
- **复跑**：`grep -oh 'font-size:[^;}]*' pwa/css/*.css | sed 's/font-size: *//' | grep -E '^[0-9]+px$' | sort -u | tr '\n' ' '`

### P7 · 圆角 21 档、无 token，存在 1~2px 近重复漂移
- **证据**：`style.css:2909` 11px（全站唯一）、`style.css:1750/2184/2588/5534` 14px、`style.css:970` 与 `records.css:1037` 26px，与主流 12px / 28px 只差 1~2px；21 个不同值无一处走 token。
- **为何是真问题**：圆角是"同一双手"最易被感知的特征，11 vs 12、26 vs 28 的差别没有任何语义理由，属于典型"逐屏补丁"指纹。可感知程度低（要并排看才察觉），故排末位。
- **建议改法（不动手）**：定 `--r-card:16px` / `--r-modal:24px` / `--r-pill:999px` / `--r-chip:12px` 四档，11→12、14→16、18→16 或 20、26→28；加一条"圆角只准取 `--r-*` 或 `50%/inherit`"的断言。此条与 v150 的 P2 记账是同一条，本轮确认未修。
- **复跑**：`grep -oh 'border-radius:[^;}]*' pwa/css/*.css | sort -u | wc -l`

## 七、最小改动建议（只列，不执行）

若只准动三处，按此顺序：
1. `.sc-net` 入数值白名单并改走 `var(--num-2)`，`.sc-name` 降到同档或低一档 —— 消除同屏两套冠军答案。
2. 8 处第 2 层裸投影就近收敛到 `--elev-*`，并把 `isElevation()` 改成逐层判定 + 显式豁免带色氛围光 —— 让"手写外投影=0"变成字面事实。
3. 定义 `--text-main`（或四处改用 `--warm-white`）+ 加一条 `var()` 引用完整性断言 —— 堵住颜色域的静默作废。

三步都不改交互逻辑、不动缩放体系、不影响性能；改完需补截图：结算静帧（390×844）、回放、座位面板、首页（验 `text-shadow`）。
