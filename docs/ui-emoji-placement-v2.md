# 表情 / 短语落点规格 v2（取代 v1「贴上/下侧居中」）

状态：待施工
取代：v1（2026-11-14 发布的 `20261112e`，规则为「底边贴座位上方，放不下翻到下方，居中后夹进视口」）
适用版本：`20261114a` / sw `v150`（施工期不 bump，发布时统一改）

## 0. 为什么改

v1 的落点是**相对座位居中**。参考游戏的做法是**贴着头像**：气泡在头像侧边，
用一个小尾巴指过去，一眼能看出「这句话出自谁」。

但「固定在头像右侧」在牌桌上不成立：最右侧座位（实测 `陪练4`，1366 宽度下
座位块右边缘 ≈ 528，卡片栏从 580 开始）右侧没有足够空间，固定的右挂必然出屏。
所以方向必须是**每个座位按可用空间算**，不是全局写死。

v1 的实际问题（用户 2026-11-14 第二次反馈）：

| 问题 | 表现 |
|---|---|
| 没有尾巴 | 气泡浮在座位上方，看不出归属 |
| 与座位的关系是「上下」 | 参考游戏是「侧边」，牌桌上横向空间更宽裕，纵向更容易撞到顶栏 |
| 只考虑锚点自己 | 没有处理「同一时刻多人发送」时的互相遮挡 |

## 1. 锚点定义

| 场景 | 锚点 |
|---|---|
| 全场广播（`to = BROADCAST`） | **发送者**座位 |
| 定向（`to = 某人`） | **收件人**座位 |
| 自己发的 | 同上两条，不特殊处理 |

> 每个客户端都按同一规则算，所以 5 个座位各自发广播时，气泡出现在各自座位旁 ——
> 「其他玩家发送」与「自己发送」走的是同一条路径，不存在只测自己就够的情况。

**座位块** = `#game-top [data-pid="<pid>"]` 的 `getBoundingClientRect()`（含头像 + 昵称 + 分数）。
**瞄准点** = 该座位块内 `.opp-avatar` 的中心（尾巴尖端朝向它）。

## 2. 方向选择（短语与表情共用顺序）

**顺序不是「右→左→上→下」（v2.1 及以前是，v2.2 改）。** 圆桌是环形布局，
座位沿弧线围一圈，中间是空桌面 —— **朝桌心的方向永远最宽**，朝屏幕外永远最紧。
固定从「右」开始试，等于把最靠边的座位直接逼进兜底链（实测：390 宽上排两个座位
对短语四方向全废，只能掉到桌下方、尾巴离人 211px）。而最右侧座位按这个顺序也必然
先试「右」再失败一次。

改为两级排序：

1. **内推优先**：`inward` = 从座位块中心指向桌子中心（全部 `[data-pid]` 块中心的重心）
   的主轴方向，吸附到 `right / left / up / down` 里最近的一个。先试它。
2. **其余按可用空间降序**：可用空间 = 该方向上从座位块边缘到最近障碍（别的座位块
   或视口边界）的距离。空间大的先试。

取第一个**满足全部约束**的位置。四方向几何定义不变：

| 方向 | 几何 |
|---|---|
| `right` | 气泡左边 = 座位块右边 + `gap`，垂直以头像中心对齐 |
| `left` | 镜像 |
| `up` | 气泡底边 = 座位块顶边 − `gap`，水平以头像中心对齐 |
| `down` | 气泡顶边 = 座位块底边 + `gap`，水平对齐同上 |

**夹取允许，且不影响该方向是否可用（v2.4）。**
「以头像中心对齐」之后再夹进视口是**合法**的 —— 只要尾巴的 `--tail-off` 还在 `[m, L − m]` 内，
它就能补偿这段位移、仍然对准头像。夹取之所以以前被当成「作废」，是因为
v2.3 的判据要求「尖端落在头像矩形外扩区内」—— 那等于要求气泡**必须**居中，夹一下就废。
v2.4 把判据改成「沿贴合边对准 + 尖端贴块」（§6 Q4a），夹取就自然成立了。

**但夹取后必须复判（v2.5 补）**：夹取会改变矩形，所以 A / B / D 三条要在夹取后的
新矩形上**重新判一遍**，不过就作废该方向。实测例：`pal2` 的 `up` 从 `y = −58` 被纵向
夹到 `8`（偏移 66），夹完立刻压到同排两块 —— 夹取不能作为「先夹进来再说」的通行证。

> 实测意义：390 宽上一句 17 字长短语宽 366，任何座位居中都会 `Ac.x ± 183` 越出视口，
> 四方向按「不许夹」判全废、只能兜底（Q8 直接 6/20，超预算 3 倍）。
> 允许夹取后落在 `down` + `left = 8`，`--tail-off = 275 ∈ [18, 348]`，尾巴照样指人。

约束（四条同时满足才算「可用」）：

- **A 完整在视口内**：留 `MARGIN = 8px` 安全边，不依赖 `#emoji-layer` 的 `overflow:hidden` 兜底。
  **测的是「裁剪盒」不是「气泡 rect」**：尾巴是 `::after`，不在 rect 里，会伸出 8px。
  **裁剪盒只朝尾巴所在的那一边外扩 `TAIL_H`，其余三边不外扩。**
  四边都外扩是**几何上不可满足**的：`vw = 320` 时气泡上限宽 `= 320 − 24 = 296`，
  每侧余量只有 12，而四边外扩要求每侧 `MARGIN 8 + TAIL 8 = 16` —— 差 4px×2，永远越界；
  390 同理。17 字长短语 `17×24 + 36 = 444` 一定顶到上限宽，所以这几格在四边口径下**永远修不绿**。
  单侧外扩恰好可行（`16 + 296 + 8 = 320` 精确成立，零余量）。
- **B 不压座位块**：
  - **短语**：与**全部** `[data-pid]` 块（含锚点自己）重叠面积 = 0
  - **表情**：与**非锚点**块重叠面积 = 0；锚点自己允许重叠（仅限「末位保底」分支，参考图里表情就是贴着人的）
- **C 尾巴位置（夹取规则，**不是**否决条件）**：尾巴沿贴合边的位置夹在 `[m, L − m]` 内，
  `m = min(18 × k, L / 2)`，`L` 为贴合边长度，`18 × k` 是气泡圆角半径。
  **注意 `m ≤ L / 2` 恒成立 ⇒ clamp 恒有解 ⇒ 「尾巴放不下」这个否决理由在数学上不存在。**
  四方向的可否决性只有 A / B / D 三条。**实现里若还留着「因尾巴放不下而放弃该方向」的分支，
  那是死代码，必须删** —— 留着会把本可用的方向误判成不可用。
  （v2 初稿在 §2 写 `12×k`、§3/§6 写 `12`，两处不一致；现统一为上式，以本条为唯一出处。）
  **尾巴瞄准优先级**：先瞄头像中心；被夹住时退化为瞄座位块 —— 这不算作废。
- **D 不与存活中的气泡相交**：见 §4

四个方向全部不可用（极端窄屏）→ 走兜底链（§4.1），**保证不丢内容**，但计入「不指人」预算。

## 3. 视觉参数（全部乘 `--emo-k`）

| 项 | 值 | 说明 |
|---|---|---|
| `gap` | 10 × k | 座位块到气泡 **rect** 边缘的距离。尾巴再朝座位方向伸 `TAIL_H = 8k`，**尖端落在离座位块 `gap − TAIL_H = 2k` 处**（视觉上就是「碰着了」）。⚠️ v2.2 曾写成「到裁剪盒边缘」，那是错的：会推出 `rect 边 = 2k`，与 §2 四条几何式的 `rect 边 = gap` 差 `8k` |
| 尾巴尺寸 `TAIL_W × TAIL_H` | 12 × 8（× k） | 与气泡同色 `#FFFBF0`，尖端朝锚点头像 |
| 尾巴偏移 `--tail-off` | JS 写，单位 CSS px | 沿贴合边对齐头像中心，夹在 `[m, L − m]`，`m` 见 §2 约束 C |
| 安全边 `MARGIN` | 8（不乘 k） | 视口硬边，与字号无关 |
| 气泡最大宽 | `min(460×k, 100vw − 24)` | 沿用；`white-space: normal` 保留折行 |
| `--emo-k` | `clamp(stageScale / 0.52, 1, 1.5)` | **上限 1.5（v2.8）**：舞台缩放无界，1920 是 2.27 —— 不封顶时短语 54px、是座位名（20px）的 2.7 倍、气泡占半屏宽。封顶后桌面统一 36px（座位名的 1.8 倍，手机是 1.2 倍），表情直径封顶 96px，仍大于 1920 的 80px 头像 |

**为什么上限是 1.5 而不是「跟头像成比例」**（v2.8，用户口径「不同设备大小要适配屏幕」）：
头像宽**跟舞台缩放走**（35 → 57 → 80），拿它当尺子等于要求气泡无界放大；
而界面文字（`.opp-name` 座位名）是**固定 CSS px**，不跟舞台走。
所以尺子换成座位名：气泡相对它有界，才是「和 UI 同一个尺度」。
代价要写明：封顶后气泡相对**头像**的比例随屏幕变大而下降（1920 上 0.45，手机 0.68），
这是有意取舍，不是回归 —— 探针的判据也随之从「字号 : 头像」改成「字号 : 座位名」。

**尾巴实现**：`::after` 画三角，方向由外层 `data-dir="right|left|up|down"` 决定，
沿边位置由 `--tail-off` 决定。阴影挂在**外层**用 `filter: drop-shadow`，
否则 `box-shadow` 不会跟着三角形走，尾巴会像贴上去的一块。

**表情（非短语）**：同样四方向；允许的例外是「末位保底」时可以与**自己的**座位块
重叠（表情是不透明图，糊住自己头像不影响读别人的话）。
表情与座位块的间距用 `4`，比气泡的 `10` 小 —— 参考图里表情几乎贴着人。

## 4. 同屏多条

同时最多 6 条（沿用）。新气泡若与某条存活气泡相交：

- 侧边放置 → 沿**垂直**方向让开，步长 = 自身高度 + `6`，最多试 3 次
- 上/下放置 → 沿**水平**方向让开，步长 = 自身宽度 + `6`，最多试 3 次
- 3 次仍相交 → 接受重叠（宁可叠，不要消失），但**仍须满足 A 与 B**

**「接受重叠」不是无限制**。判定口径（v2 初稿写「重叠条数 ≤ 1」与本节矛盾，现以本条为准）：

- 计数单位是**重叠对数**，不是条数：`pairs ≤ 1`
- 且这一对必须**可解释为轴饱和**：在让开轴的方向上，视口内**不存在**能放下
  自身尺寸 + `6` 的空位。用这条谓词代替「内部循环跑了几次」——
  后者不可观测，前者可独立复算

### 4.1 让位方式（v2.2 新增，v2.6 改）

v2.1 写「上/下放置沿水平方向让开」。**这条路是错的**：上/下的尾巴长在横向边上，
水平让位直接把 `--tail-off` 拉走，尾巴立刻不指人 —— 实测 320 宽上只剩 2px 余地，
让一步尖端距就 50.6px（阈值 20.1）。两头互相否定。

v2.2 改成「按自身边长 + 6 整块换行」。**这个步长也不对（v2.6）**：它太粗，
明明有空间却跨不过去。390 实测：`陪练2` 的 `down` 气泡跨 `49..205`，
与左侧块（右沿 92）相交；整块右移一步 162px 又撞 `陪练3`。可是中间 `95..251`
这一段其实是空的 —— **粗步长把「挪一点就够」判成了「没法挪」**。

**v2.6 改为区间搜索**：不再用固定步长，直接求满足条件的位移区间。

- `up / down`：在 **x** 上搜索；`left / right`：在 **y** 上搜索
- 合法条件 = A ∧ B ∧ D 在**位移后**的矩形上重新成立
- **位移上限由尾巴决定**：尾巴必须仍对准头像（Q4a 横向条件），
  所以允许的位移幅度 = 让尖端仍落在头像跨度内的最大距离。
  超出这个幅度的一律不可用 —— **气泡可以滑，尾巴不能撒谎**
- 优先选**位移最小**的解（离对齐位置最近 = 观感最自然）

换行（`place='stack'`）保留为区间搜索之后的次选；仍不行才接受重叠（§4 正文）。

### 4.2 「不指人」预算（v2.2 新增，v2.6 改口径）

兜底是固有代价，但不能无限：内容没丢 ≠ 归属清楚。

**v2.6 起，预算只统计「不指人且未署名」**（v2.5 加署名之后，这两件事必须分开算）：

| 档位 | 「不指人且未署名」上限 | 理由 |
|---|---|---|
| 320×568 | ≤ 2 | 屏太窄，长短语物理上无法指人，但署名能兜住归属 |
| 其余各档 | ≤ 2 | 同上，统一口径 |

**「不指人但已署名」不计入阻断**，但要接到出口判定上（v2.7 补）：每档 ≤ 8 条，
**超过则该档最高只能判「有条件通过」，且必须写进发布说明**。

这一条防的是一条真实的假绿通道：20 条全兜底 + 20 条全署名 → `未署名 = 0`，
阻断项满分，而实际上**一条都没指到人**。观察项只记录、不接出口，这条路就能过。
`≤ 8` 同时保证定向落点天然 ≥ 12/20，所以不需要另发明一个「定向率」百分比 ——
没有独立来源支持某个百分比阈值，把 `≤ 8` 用足即可。

探针必须同时输出三个数：`定向落点 / 不指人但已署名 / 不指人且未署名`，
且 **三者之和必须严格等于分母**（不等即判「该档未测」，不设容差 ——
漏掉的气泡恰恰是最差的那几条，漏完就全绿）。
两类危害不在一个量级：
- 不指人但署名 → 用户仍知道「这是陪练3 说的」，只是位置不够优雅
- 不指人且未署名 → 用户不知道谁说的，**这是功能失效，不是观感问题**

### 4.3 兜底署名（v2.5 新增，解窄屏物理限制）

**问题**：390 宽上一句 17 字长短语宽 366、折行后高 82，加上 `gap` 需要约 92 的
竖直净空。而 390 档四段横向净空带的高度只有 **26 / 42 / 29 / 575** ——
前三段装不下任何一句话，第四段（`261..836`）里没有任何座位块可贴。
所以除「我」以外，其余 4 个座位的 4 个方向**全部被 B 否决**（QA 离线 oracle 逐格算过，
`A = 0 / D = 0 / B = 16`）。这不是实现 bug，**是窄屏上的物理限制**：
366 宽 ≈ 屏宽 94%，无论怎么摆都会跨过邻座。

**裁定**：Q4b 不成立（尾巴碰不到块）时，气泡**必须署名**，让归属不依赖尾巴。

| 内容 | 兜底时的样子 |
|---|---|
| 短语 | 正文前加前缀 `昵称：`，字号 `0.8 × 正文`、同色 70% 不透明度，与正文同一行内联 |
| 表情 | 图片下方加一行 `0.7 × 基准字号` 的昵称小字，居中 |

昵称从 `state.room.players` 按 `ev.from` 取；取不到用「对方」。

**为什么是署名而不是别的**：
- 收窄气泡 → 18 字挤成 4~5 行，字号还得降，等于用可读性换个尾巴
- 放宽 B → 用户最初投诉的原话就是「正好糊住对方头像，连名字一起挡掉」，放行名字等于把投诉的一半合法化
- 加长尾巴当引线 → 78px 的三角不像尾巴，像故障
- **署名是聊天软件三十年的标准做法**：指不过去的时候，就用文字说清是谁

**它同时解掉 320 档的 S1**：320 上「我」的座位三类内容全部兜底、不再指人，
加了署名之后归属仍然明确。

**尾巴只在 `reach === true` 时绘制**；`reach === false` 时尾巴退场，归属只由署名承担。
「兜底」是**落点链的名字**，不是这条规则的前提 —— 不要把两者写成同义词。

> 口径收窄说明（2026-11-14，实现与判据同源后修正）：原句写的是「**兜底落点不画尾巴**」，
> 而实现里决定画不画的是 `spot.reach`（Q4b），不是 `spot.place`（`seatSheetView.js:1026` 加署名、
> `:1061` 关尾巴都读 `!spot.reach`）。本轮 120 格里两者恰好一一对应，所以旧写法看不出问题 ——
> **但它焊死的是「恰巧」，不是「必须」**：兜底位置若仍然够得到锚点，尾巴照画、署名不加。
> 详见 `docs/impl-emoji-placement-v2.md` §10 条目 29。

方向（`data-dir`）仍然记录：它描述气泡在座位哪一侧，探针 Q3 还要用它；但 `reach === false`
时**不再声称指向锚点**。依据是实测：320 那条长短语的尾巴末端压在「陪练4」底下，
**指错人比不指人更糟**。

**否定式判据（Q10）**：兜底条数中，**署名覆盖率必须 = 100%**。
「不指人」可以容忍（物理限制），「不指人且不署名」不能容忍 —— 后者是纯粹的「不知道谁发的」。

## 5. 跨设备

| 档位 | 关注点 |
|---|---|
| 320×568 | 两侧都放不下 → 必须走「上/下」；气泡折行后高度变化要参与 B/C 判定 |
| 390×844 | 手机基准，`k = 1`，观感即基准观感 |
| 844×390 横屏 | 顶栏改左右两栏布局，座位 x 跨度大、y 空间小 → 左右挂更常用 |
| 800×600 / 1366×768 / 1920×1080 | 桌面，`k` 1.2~2.3 |

PWA 独立窗口与浏览器同源同逻辑，不额外分支；`MARGIN` 保证不贴边。

## 6. 验收判据（几何，可自动）

对 **5 个座位 × 4 类内容**（短短语 / 长短语 / 表情 / 定向表情）逐个作为锚点验证：

| # | 判据 | 阈值 |
|---|---|---|
| Q0 | **测量契约**（先定这个，否则数字跨轮次不可 diff） | ① 量气泡**内层** `.emoji-pop` 的 rect；② 裁剪盒 = rect 外扩 `TAIL_H × k`（尾巴不在 rect 里）；③ 测量窗口锁 `spawn 后 [770, 1400] ms`（落定 430 + 回弹 340 = 770，1500 开始淡出上浮）；④ 合成发送间隔 ≥ `2100 ms`（2 秒节流会静默丢弃第二条） |

  且尖端仍须满足 Q4b
- 新增 **N18「尾巴撒谎」**：`|shift|` 超界计 1，**`shift` 字段缺失本身也计 1**

**为什么 QA 的反对必须采纳（误伤评估）**：我给的替代条件是 `gap ≥ 2k`，
那等于允许气泡贴到离块 2px、G5 照样绿 —— 「把气泡往块上怼」就成了过关捷径，
正是我自己担心的「为过 G5 把搜索关掉」的**镜像版本**。
坚持 `gap` 精确，搜索就只能沿平行轴滑：滑不出贴脸，也滑不到离块太远，两头都堵住。
**这不是提高门槛，是这条豁免本来就不需要。**

**另外采纳 QA 两条它自己加的、我没要求的**：
1. **N16：三数之和必须严格等于分母**（不等即判「该档未测」，不设容差）。
   漏计的气泡恰恰是最差的那几条，漏完就全绿 —— 这是唯一能抓「统计口径错」的断言。
2. **`已署名 > 8` → 该档最高只能「有条件通过」**。理由硬：v2.6 拆口径后出现了
   唯一一条「阻断项满分却什么都没做到」的通道 —— 20 条全兜底 + 20 条全署名
   → `未署名 = 0`、满分，而一条都没指到人。观察项只记录、不接出口，这条路就能过。

**QA 自我推翻一条也记下来**：它初稿把「不同发送者的署名全同」写成 FAIL，
写样本时发现**两名玩家真叫同一个昵称时实现照抄是正确的**，判红等于拿数据撞名去怪实现，
于是自己砍了那条 FAIL、降级为 WARN —— 而「硬编码一个人名」这种假绿由逐条内容比对挡死。
这是「误伤评估」用对的例子：**判据宁少一条，不要多一条会误伤真实现的**。

**历史数据不许换算**：`§13.5` 那份 `Q8=3/20`、`6/20` 全部作废，且**禁止按新口径拆分**——
拆成「已署名 4 + 未署名 2」需要逐格的 `.emoji-by` 事实，而那一轮跑里根本没有这个元素。
换算等于编数据。

## 15. 测量链的三个洞（v2.7 实测，2026-11-14）

六档连跑之前，探针与跑批脚本本身有四处问题，每一处都会让**数据看起来正常、结论全错**。
记在这里，因为它们不属于「摆放算法」，却决定了算法有没有被真正验过。

**① N18 的判据只能是「尖端 vs 脸」，`shift` 只配当「算没算过」的开关**
`shift` 是**气泡**的位移量，尾巴不跟着滑（`--tail-off` 是按落定后的 rect 算的）。
所以「位移是否在预算内」不能拿 `shift` 判 —— 气泡滑得远、尾巴照样指得到人是合法情形。
- `shift` **缺失** = 这条落点根本没经过对齐（兜底链没有基准）→ 计 1
- 位移是否超界 → 用**尖端是否仍在脸跨度内**判（与 Q4a 轴线①同义）

实现里故意**不给兜底落点写 `data-shift`**，就是为了让「没位移」与「没算过」可区分；
把缺失当 0 的写法会把一批没测过的格子算成通过。

**② 跑批脚本没把 `SEATS` 传给探针** —— 前置检查要 5 座，探针自己默认 2 座，
于是每一档都要跑满 4 分钟才被判「座位数不对」。**配置在两处各写一遍，就必然会漂。**

**③ `avatars:N` 的正则只认裸值**
探针把这行打成了 JSON 片段（`"avatars":5`），旧正则 `/avatars:\s*(\d+)/` 全部匹配不上，
六档会被**统一**判成「找不到自报 → 前置失败」。一个正则足以废掉整轮数据，
所以自验里加了两种写法各一条。

**④ 进程被杀后 `.lock` 不释放**
单实例锁本来是防「两份半数据拼成全量」的，结果反过来制造「跑不了」的僵局。
改为按 **pid 存活**判陈锁（不是按时间猜 —— 一档跑多久取决于机器），
并给 `mkdir` 到写 `owner.json` 之间的空窗留 600ms，避免把正在启动的档误杀。

**另外两处判定口径的修正（都会造成假红/假绿）**：
- 「发出去的短语文案一致」原来用 `textContent` 全量比对，§4.3 加了「昵称：」前缀之后必红。
  改成**排掉 `.emoji-by` 子树后再比正文**（TreeWalker 逐文本节点，不是字符串截前缀 ——
  昵称本身带「：」时截前缀会切错）。
- 本机 id 固定为 `me`、昵称固定为「我」（`sessionStorage.lxw_myid_v1` + `RoomStore.rename`），
  dump 每行新增 `fromName`（从座位块 `title` 独立读）。
  **署名判据的 oracle 必须来自「事实」而不是 fixture** —— fixture 猜不中就记未测，
  而未测一多，结论就只能降级成「有条件通过」。


## 15. 修订记录（v2.8，2026-11-14 夜，用户口径「不避让，但大小要适配屏幕」）

**触发**：长短语在 1366 / 1920 会盖住自己的手牌 1.9 秒。我先给了「把手牌区并入避让集
+ 兜底降字号」的方案，并算出「只靠缩字号要缩到 46%（17.7px），比座位名还小」。
用户裁决：**不避让、可以遮住（连头像也可以），但不同设备的尺寸要适配屏幕。**

**真正的病因不是落点，是尺子选错了**：
`--emo-k = stageScale / 0.52` 是**无界**的，1920 上舞台 1.182 → k 2.27 → 短语 54px。
而界面文字（`.opp-name` 座位名）是**固定 CSS px**（20，横屏 24），根本不跟舞台走。
于是同一句话的字号对座位名的倍数：手机 1.2 倍、1920 是 **2.7 倍**，气泡宽占半屏。
「电脑上显得太大」是这件事的直接后果，跟遮不遮手牌无关。

**裁定**：`--emo-k = clamp(stageScale / 0.52, 1, 1.5)`。

| 档 | 舞台 | k（旧→新） | 短语字号 | 气泡宽（旧→新） | 占屏宽 |
|---|---|---|---|---|---|
| 320×568 | 0.427 | 1 → 1 | 24 | 296 → 296 | 93% |
| 390×844 | 0.567 | 1 → 1 | 24 | 366 → 366 | 94% |
| 844×390 / 800×600 | <0.52 | 1 → 1 | 24 | 420 → 420 | 50% / 53% |
| 1366×768 | 0.841 | 1.62 → **1.5** | 38.8 → **36** | 680 → **630** | 50% → **46%** |
| 1920×1080 | 1.182 | 2.27 → **1.5** | 54.4 → **36** | 953 → **630** | 50% → **33%** |

表情直径同步：1366 104 → 96、1920 145 → 96（仍大于 1920 的 80px 头像，
不会退回 v148「表情比头像还小」那一轮的病）。

**为什么上限是 1.5 而不是「跟头像成比例」**：头像宽**跟舞台走**（35 → 57 → 80），
拿它当尺子等于要求气泡无界放大；座位名是固定 px，拿它当尺子才有界。
代价写明：封顶后气泡相对**头像**的比例随屏幕变大而下降（1920 上 0.45，手机 0.68），
这是有意取舍。探针判据随之从「字号 : 头像宽 ∈ [0.60, 0.78]」改成
「字号 : 座位名 ∈ [0.95, 1.85]」（未封顶的 1920 是 2.7，照样能抓住）。

**副作用（正面的）**：1920 档变小之后，落点自己从「压在牌上」挪到了牌**上方**的桌布空带，
尾巴照样指着「我的分」—— 没有加任何避让逻辑，是尺寸变小后规划器自己找到的空位。
1366 仍会压住左侧 4 张牌的下半（牌面点数在上半，仍可读），按用户口径「可以遮住」保留。

**验证**：六档同源 `probe 4ccebdd4`，全 0 失败；`Q8 定向/已署名/未署名`
仍是 `17/3、16/4、20/0 ×4`（与 v2.7 逐档一致）；全量单测 171/171、7129 断言；
真人路径 1366 / 1920 各 34/34。
