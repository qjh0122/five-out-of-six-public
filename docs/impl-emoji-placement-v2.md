## 二、系统实现方案

### 2.1 落点规划 `planSpot()`（`pwa/js/seatSheetView.js:576` 起）

**职责**：给定气泡尺寸、锚点座位块、四个方向，返回 `{ left, top, dir, tail, tip, reach, shift, place }` 或 `null`。纯测量 + 纯计算，不碰动画。

**数据结构**

| 名字 | 含义 |
|---|---|
| `ab` | 锚点座位块 `[data-pid]` 的 rect（**含昵称与分数**，B 判据压的是整块） |
| `av` | 块内 `.opp-avatar` 的 rect（尾巴对齐用它，`acy`/`acx` 是它的中心） |
| `cap(dir)` | 该方向的可用空间，**允许为负**（= 已经被挡住） |
| `base` | 该方向的**对齐位置**：`{ left, top, vert, span }`，`span` = 沿自由轴的自身跨度 |
| `m` | `min(18 × k, span / 2)` —— 尾巴中心离气泡角的最小距离（约束 C 唯一出处） |
| `reach` | **Q4b 是否成立**（尖端在座位块外扩 `gap + TAIL_H` 内）。它只触发署名，**不否决方向** |
| `shift` | 相对对齐位置滑了多少（`Math.round(实际落点 − 对齐位置)`，**夹取之后**的值） |

**关键流程**

1. **方向排序**（规格 §2 两级）：`inwardDir()` = 本块中心指向「全部 `[data-pid]` 块中心重心」的主轴；其余三个按 `cap()` 降序；相等退回 `right/left/up/down`。
2. **`judge(dir, base, left, top, opt)` 只判三条**：
   - **A** 裁剪盒在视口内 —— **单侧**外扩（`dir==='right'` 时只扩左边，其余三边只留 `MARGIN`）。四边外扩在 320/390 上几何不可满足（上限宽 296/366，两侧余量 12 < 8+8）。
   - **B** 不压任何别人座位块；锚点自己单独判（只有表情的「末位保底」放行）。
   - **D** 不与存活气泡的**落点矩形**相交（用 `__land`，不用飞行途中的 rect）。
   - `left/top` 先按 A 夹进视口，**B / D 用的就是夹取后的新矩形** —— 这是 v2.5「夹取后必须复判」的实现位置。反例：`pal2` 的 `up` 从 −58 夹到 8，夹完立刻压两块，于是该方向作废。
3. **C 只记录不否决**：`m ≤ span/2` 恒成立 ⇒ clamp 恒有解 ⇒「尾巴放不下」在数学上不存在。删掉的那段代码实测误杀过：**390 满员局 41 次**（right 22 / left 18 / down 1）、**1366×768 6 次**（up 2 / right 1 / left 1 / down 2）。
4. **`shiftSearch(dir, base, opt)`——区间搜索**（规格 §4.1，替掉 v2.2 的「自身边长 + 6」）：
   - 侧边档在 **y** 上搜、上下档在 **x** 上搜；
   - 候选 = 对齐位置 + 每个障碍的「刚擦过」边（座位块 + 存活气泡）+ A 窗口两端，**整数化时朝外取整**（右/下 `ceil`、左/上 `floor`）；
   - 排序按 `|位移|` 升序取第一个过 A∧B∧D 的；
   - **位移上限**：`|位移| ≤ (span/2 − m) + 头像沿该轴跨度/2`。超了尖端就会被夹到角上、指不着人 —— **气泡可以滑，尾巴不能撒谎**。

**对外接口**：`planSpot(w, h, anchorEl, k, gap, skipNode, allowSelf)` → `spot|null`。`spot.reach` 给署名用，`spot.shift` 给探针 N18 用。

### 2.2 兜底链 `fallbackSpot()`（`:834` 起）

**职责**：四方向全废时保证不丢内容。顺序：贴座位上方 → 放不下翻到下方 → 夹进视口 → 沿水平让位 → 逐块下推（每行 = 自身高度 + 6）。

**与 v1 的差别**：① 下推躲的是**整块座位**（含昵称分数），不是只躲头像；② 下推后还要躲**存活气泡**。

**本轮新增**：返回 `tip` 与 `reach`。兜底常常碰不到块，那正是 §4.3 要署名的条件 —— 不能默认它「指到了」。

**对外接口**：`fallbackSpot(w, h, anchorEl, k, gap, skipNode)` → `spot`（`place: 'fallback'`，**不写 `shift`**）。

### 2.3 `playEmoji()`（`:917` 起）—— 两遍测量

**职责**：造 DOM、量尺寸、要落点、写 `data-dir` / `--tail-off` / `data-place` / `data-shift`、飞过去。

**关键流程**

1. 造节点（短语 `span` / 表情 `img`），写 `--emo-k`，`appendChild`。
2. **量尺寸用 `getBoundingClientRect()` 的小数宽高**（`wrapSize()`），**不用 `offsetWidth/offsetHeight`**（后者是整数）。
3. `planSpot(...) || fallbackSpot(...)`。
4. **`if (!spot.reach)` → 加署名、重测、重算一次**（**只一次，不迭代**）。迭代会振荡；副作用是「重算后其实指得到了但署名已经加上」—— 不违反任何判据（Q10 只要求兜底那条必须有，不禁止别处有）。
5. 写 `data-dir` / `--tail-off` / `data-place` / `data-shift`、`__land`，再飞。

**对外接口**：`playEmoji(ev)`，`ev = { id, from, to }`。昵称由 `senderName(ev.from)` 从 `state.room.players` 取，取不到用「对方」。

### 2.4 尾巴与署名（`pwa/css/emoji.css`）

- **尾巴**：`::after` + `clip-path`，尺寸 `--tail-len`（8k）/ `--tail-w`（12k），方向靠外层 `data-dir`，沿边位置靠 `--tail-off`（**原点约定写在注释里**：right/left 从上边量、up/down 从左边量，都量到尾巴**中心**）。阴影挂外层 `filter: drop-shadow`，否则三角不跟着投影。
- **署名**（v2.5 / §4.3）：
  - 短语：正文前内联 `昵称：`，`0.8 × 24 = 19.2` 设计 px、`opacity: .7`；
  - 表情：图**下方**一行小字，`0.7 × 24 = 16.8` 设计 px、居中、`#FFFBF0` + 细阴影（毡面是深绿）。
  - 表情那条要排到图下面，外层从「定宽 64×64」改成纵向 flex（`width:auto`），否则小字会溢出气泡 rect —— 而 Q2 量的是气泡 rect，看不见这一行。
  - **不动 `--emo-k` 的基准值**，两个系数只是乘在正文 24 上。

| `tools/qa/out/<tag>.NOT-RUN` 首行 | `emoji-tier-status.js` | **实际实现（runner v2.7）**：首行 `<reason> exit=<code>`（只有两段、一个空格），第二行起人读详情。**9 个冻结码**见下表；下游只取首行第一个空白分隔段，禁 `includes()` |

#### `exit` → 标记 → QA 状态（唯一判定表，改这张表之前先说）

| 探针退出码 | 写什么标记 | dump 收不收 | QA 侧状态 |
|---|---|---|---|
| `0` | 清空全部旧标记 | 收 | `OK` |
| `1`（断言失败） | **不写 `NOT-RUN`** | **收** | `FAIL-EXIT` |
| `4` / `7` | `probe-error` / `spawn-error` | 不收 | `NOT-RUN` |
| `5` | `timeout` | 不收 | `NOT-RUN` |
| **其它任意非 0（2/3/6/…）** | **`nonzero-exit`** | 不收 | `NOT-RUN` |
| 座位数 / 自报不符 | `PRECONDITION-FAILED`（不写 `NOT-RUN`） | 不收 | `FAIL-SEAT` |

**9 个冻结原因码**：`parse-fail` / `probe-missing` / `lock-busy` / `spawn-error` / `probe-error` / `timeout` / `no-dump` / `readback-mismatch` / `nonzero-exit`。
（`precondition` **不是** `NOT-RUN` 码 —— 它由 `PRECONDITION-FAILED` 表达。「跑了但数据不合格」与「根本没跑成」必须分两个文件，否则读的人只能猜。）

**为什么 `exit=1` 不写 `NOT-RUN`**：`exit=1` 意味着探针**跑完了**、只是有断言判红。这时 dump 是真实数据，**必须让 QA 看见是哪一格红了**；打 `NOT-RUN` 等于把「有数据的红」降级成「没数据」，是信息损失。而「其它非 0」在本探针里根本不会被主动产生（只有 0/1），所以出现即是异常 —— 归 `nonzero-exit`。

⚠️ **两个「1」不是同一个 1（极易混，必须分清）**：
- `meta.exitCode` = **探针**（`scripts/probe-emoji.js`）的退出码：`0` 全过 / `1` 有断言判红。它**才**是上面这张表的输入。
- **跑批器自身的进程退出码**（`runTier()` 的 `return 1/3/6` 等）= 「这一档没跑成 / 锁被占 / 预检失败」，**不写进 meta**，与探针无关。
- 于是 `meta.exitCode=0` 且跑批器 `return 1` 是**正常组合**（探针跑完了，但座位数不对 → `PRECONDITION-FAILED`）。**读 meta 的人只看 `meta.exitCode`，不要拿跑批器退出码去套上面那张表。**

**格式漂移的教训（本轮真实发生）**：写入方改成 `<reason> exit=<code>`（空格分隔）后，读取方仍按 `<reason> | probe=… | exit=…` 匹配，**四种真实 marker 全被读成「原因码不可识别」**，而状态判定靠文件存在所以照样 `NOT-RUN` —— **挡路能力还在、分流能力全废**，且两边自验各自全绿（各锁各的格式）。
**规矩**：格式的唯一样本必须来自**写入方的真实产出**，禁止各自在自己的自验里锁自己的写法。落地方式：runner 提供 `--emit-notrun-sample <dir>`，读取方的自验**消费那份真实文件**再断言；任何一方改格式，另一方的自验立刻红。

## 六、技术债与风险

1. **两份几何代码**：实现与尺子各写一遍 `availableSpace`/`judgeAt`/`shiftSearch`。刻意的（独立复算才有意义），代价是改排序或改位移上限要改两处 —— 靠 `emoji-placement-oracle.test.js` 的「常量同源」兜住常量，**算法靠人**。
2. **探针 Q4a 的分母包含兜底条**：规格写的是「定向落点中 ≥80%」，探针实际把 `e1` 全部条数（含 `place=fallback`）都算进分母 —— 比规格更严。320 的 4/5 就是这么来的（S1 的定向表情在兜底）。若要严格按规格，应改成只数 `place ∈ {dir,self}`，本轮**没改**（改严不改松，先报出来）。
3. **署名只加一次、不迭代**：见 §2.3 第 4 步。极端情况下「加了署名之后其实又能指人了」会留着署名 —— 无害但多余。
4. **`place='stack'` 仍是区间搜索之后的次选**，探针的 Q3/Q4b 只对 `place ∈ {dir,self}` 断言，另用「定向落点占比 ≥ 60%」防全退化。
5. **每帧多次 `getBoundingClientRect`**：一次落点最多 4 方向 × ~10 候选 × (5 座位块 + 6 气泡)。390 宽 5 条连发无明显掉帧；上限提到 20 条以上时需按帧缓存 `seatBoxes()`。
6. **探针的 `Date.now` 快进**只存在于 `scripts/probe-emoji.js`，跑完还原；副作用：跑完应用内 `lastEmojiAt` 是未来时间戳，手发会提示「慢一点」。
7. **无「跟随座位移动」的重排**（规格 §7 不做）。横竖屏切换时正在飞的气泡不重算 —— 1.9 秒的东西，接受。
8. **窄屏物理限制不会消失**：390 上 366 宽的长短语（≈屏宽 94%）在 B 判据下四方向全废，这是几何事实，署名是「让归属不依赖尾巴」而不是「让位置变好」。

### 7.4 844×390 / 800×600 / 1366×768 / 1920×1080

## 十、踩到的坑（按发生顺序，含本轮新增）

1. **亚像素：`offsetWidth` 是整数，渲染 rect 是小数**（本轮最贵的一个）。1920 档 `k=2.27`，表情实际 145.27 宽而 `offsetHeight` 只给 145；规划用整数、`__land` 用整数，探针量渲染 rect → 差 0.27px，Q6 报 `29px²` 重叠且「轴饱和」谓词说有空间（判红判得对）。修法：两处测量都走 `wrapSize()`（`getBoundingClientRect` 的小数宽高），并在 `shiftSearch` 里把候选**朝外取整**（右/下 `ceil`、左/上 `floor`）。**只要有一个地方还在用整数尺寸，这类假重叠就会回来。**
2. **模板字符串里不能出现反引号**：探针把整段判据写在 `evaluate(\`…\`)` 里，注释里写 `` `昵称：` `` 会把模板提前截断，报 `SyntaxError: missing ) after argument list`（错误指向 `evaluate(` 那一行，完全不提反引号）。改注释即可。
3. **端口被上一次没退出的进程占着**：表现不是报错，而是「探针没有输出」。根治：`PORT` / `CDP_PORT` 都改成环境变量可覆盖（施工方 3051/9361，QA 3047/9357，默认值不变）。
4. **改台账后忘了重新生成文档**：`run-tests.js` 会红在「文档内容 == 用当前台账重新生成的内容」，先 `npm run probes:doc`。
5. **两个人同时改同一批文件**（本轮真实发生）：一边在写 `seatSheetView.js`/`probe-emoji.js`，一边在起 tier 跑。中间有一个不到 10 秒的窗口文件是半成品（`'use strict'` 下缺 `var i` 会 `ReferenceError`），那一轮跑出来的数字不能要。**约定：改文件的与跑探针的错开，或先 `node --check` 再起跑。**
    - **本轮加重（19:45–19:49，同一个文件两次叠加写入）**：`scripts/probe-emoji.js` 上先有 team-lead 的 `c304cca5`，约两分钟后又有我的 `ddb9f2bc`，此后**谁都无法仅凭记忆证明盘上那一版是自洽的**。事后核验靠的**不是人证，是三件物证**：① `sha256sum` 单值（`ddb9f2bc…`）；② 六份 `.meta.json` 的 `probeSha256_16` **同值**（六档同源）；③ 双方各自记得的改动点用 `grep -n` 逐条对得上（`data-tail` / `absent ? 0` / `tailAbsent` 进 dump / `碰块=n/a` / 双向断言 / `t4judged` 分母排除）。
    - **纪律定死：一个文件同一时间只有一写者；交接靠「先停手 + 报 sha」，不靠「应该没冲突」。** 增量写入（`Edit` 读盘上现状再改）能保住对方改动，全量重写（`Write` 一份旧缓冲区）不能 —— 本轮没出事是因为走的是前者，**这是运气不是流程**。
6. **判据在两处用不同口径实现**（本轮又出现一次：Q1 四边/单侧、Q4a 矩形/两轴）。规矩：**探针是唯一实现，尺子只复算**；两边不一致时先查新旧两式并存。
7. **`gap` 口径**：`gap` 量的是座位块到气泡 **rect** 的距离（`10k`），不是到裁剪盒。写成「到裁剪盒」会把 rect 边压成 `2k`，四方向的几何式全部差 `8k`。
8. **阴影必须挂外层**：`box-shadow` 画的是圆角矩形，`::after` 的三角不参与，视觉上尾巴像贴上去的一块。
9. **动画会覆盖 transform**：位移与回弹必须在两层 DOM 上（`.emoji-fly` / `.emoji-pop`），否则回弹一跑气泡就跳回屏幕左上角。
10. **`__land` 而不是 `getBoundingClientRect`**：前一条还在飞时 rect 是半路位置，用它判「会不会压住」会在落地后才暴露重叠。
11. **判据别写「不可能条件」**：Q4a 旧式对 `down` 永远不成立（头像在块顶部），Q4b 早期版本对「挂在下边」也不成立。**判据错和几何无解长得很像，区别是前者会在所有档位上都红。**
12. **`git stash` 拿「改前数据」会把当轮改动一起 stash**：本轮踩过，恢复后再也不这么干 —— 改前数字一律以文档记录为准。
13. **探针 Q1 曾按「四边各减 TAIL_H」**：在 320/390 上几何不可满足（上限宽 296/366，两侧余量 12 < 16），10 格永远修不绿。单侧外扩恰好成立（`16 + 296 + 8 = 320` 零余量）。
14. **Q8 别用一个合计数**：它会把「不知道谁说的」和「位置不够优雅」混在一起，于是任何改进都只能体现在「把数字调大」上。
15. **同一个配置在两处各写一遍，必然漂**：跑批脚本（`tools/qa/emoji-run-tier.js`）的前置检查要求 **5 座**，探针自己的默认值是 **2 座** —— runner 早先没把 `SEATS` 传下来，于是「前置说满员、探针按两人局跑」，20 格的落点全变了样。修法：`SEATS` 由 runner 单向下传，探针不再自己决定；`SEATS` 只在 `pwa/js` 之外的一处出现。**任何「座位数 / 视口 / 缩放」这类跑批参数，只允许有一个来源。**
16. **`avatars` 自报被打成了 JSON 片段**：探针把多个自报值拼成一条日志，`avatars` 那条实际输出成 `"avatars":5`（带键名和引号），而下游的正则只认裸数字 `\d+` → 六档会被**统一**判「找不到自报」，看起来像「实现没写」，实际是日志格式问题。修法：自报行统一成 `键=值`，下游客器正则只认这一种形状。**「找不到」和「没写」必须能区分 —— 日志形状也算契约。**
17. **`shift` 一个字段两种语义，且两轴写反**（本轮最隐蔽的一个，被两边各误用一次）。原式 `(vert ? spot.left : spot.top) - basePos` 在 `vert` 分支拿 **x 减 y**；同一字段在「换行让位」那条路径上写的是**候选偏移**、在「区间搜索」那条上写的是**实测位移**。后果：team-lead 据此写了错判据（`|shift| ≤ 头像半跨`，误红 16/20），QA 据此引用了「位移 215px」的结论（该数作废）。**定位特征**：320 视口只有 `-26`、390 却有 `215`，差值恰好等于视口差 —— 差值与几何量成比例时，先查坐标混轴，而不是查算法。
    - 修正后语义钉死：`shift = 实测落点(vert? top : left) − 基准位`，**带符号、零位移写 `0`、键不许省**；`0` 是合法值，下游写 `if (!shift)` 会把这 8 行打成「未测」。
    - **`shift` 仍然不是「尾巴偏移」**：`up/down` 上是 x、`left/right` 上是 y，而 `--tail-off` 会反向补偿。所以「尾巴有没有撒谎」只能落 `tip` vs `face`，`shift` 只用来判「有没有算过」。
    - 通用教训：**判据与实现共用一个错字段，错会被放大两倍**，而且两边会互相「验证」通过。字段的定义要写在被读的那一侧（探针 dump 的字段表），不是写在写的那一侧。
18. **截图段不能放在会假造时钟的扫描段之后**：扫描段为了让 20 条在 ~44 秒内发完，把 `Date.now` 改成「每调用 +2500ms」；房间记下的 `lastEmojiAt` 因此是**未来**时间戳，时钟一还原，后面每条都被 2 秒节流**静默丢掉**（等 2.3 秒没用，要等 50 秒）。第一版把「兜底署名实物」截图放在收尾，拍出来是一片空桌面，日志却写着「截图：…signed.png」—— **假证据比没证据更糟**。修法：该段整体挪到扫描段**之前**、用真时钟；并且收尾那一份旧副本已删除（它每次都打印一行「多半又被 2 秒节流丢了」的误导性警告）。

### 10.1 已知限制（细节）
19. **`Page.captureScreenshot` 在合成面宽度 > 4096 时永久挂住**（原标题是「`1920×1080` + `ZOOM=1` → 挂住」，**归因已修正**）。
    - ✅ **修正后的结论（20:30）**：两次独立挂死 —— ① `1920×1080 @ deviceScaleFactor=2` → 合成面 **3840×2160**（面积 8.29M）；② `1366×768 @ E9_DPR=3` → 合成面 **4098×2304**（面积 9.44M）。`ZOOM` **不是原因**（它全文只开关截图调用，改不了任何布局），它只是恰好让 1920 档撞上这条线的一个参数。
      ⚠️ **但「合成面宽度 > 4096」这个说法和 ① 不符**：① 的宽度是 **3840 < 4096**。所以两次的共同因子只能表述成「**合成面远大于 2K（≥ 3840 宽 / ≥ 8.3M 像素）**」；`4096` 这个具体阈值**只被 ② 支持，① 是反例**。**要定边界必须做一次阶梯实验（3840 / 4096 / 4352 各一次），本轮没做** —— 在此之前「> 4096 必挂」只能当经验规则，不能当边界值。
    - 现象（原始记录，保留）：同一版探针、同一档，带 `ZOOM=1` 必挂（`exitCode=5`、300.69s 打满 runner 超时、`records=0`、日志只剩 2 行）；去掉 `ZOOM=1` **62 秒跑完并通过**（`recs=20 / seats=5/5`）。
    - **复现次数**：不带 `ZOOM` 已成功 **2 次**（61.7s / 61.8s，同 sha `2df71f6a`，均 `116` 行日志 + 0 张截图）；带 `ZOOM` 失败 **1 次**（300.69s）。**「同 sha 两次成功」只证明「该档在不带 ZOOM 时稳定」，不证明 ZOOM 是原因** —— 带 ZOOM 的单变量复跑尚未做（见下）。
    - 触发条件：`Emulation.setDeviceMetricsOverride` 的 `deviceScaleFactor:2` × `1920×1080` = **3840×2160 合成面**，且页面是带合成层的游戏页（不是空白页）。
    - **已排除的错方向**：空白页上隔离实测 `Page.captureScreenshot`（真 Edge、`dsf=2`）1366→**96ms/22KB**、1920→**146ms/35KB**，差两个数量级 → **不是「图太大/编码太慢」**。别按这个方向去调超时或关 GPU。
    - **`ZOOM` 到底改了什么（唯一作用点，代码级）**：`process.env.ZOOM` 在 `scripts/probe-emoji.js` 里**只出现一次**（`:41` `const SHOTS = !!process.env.ZOOM`），只决定要不要调 `Page.captureScreenshot`；`Emulation.setDeviceMetricsOverride` 的 `deviceScaleFactor: 2`（`:176`）**与 ZOOM 无关、恒定开启**，也**没有** `setPageScaleFactor` 或任何 CSS `zoom`。
      ⇒ **ZOOM 不改变任何布局**（字号、尾巴、`--emo-k`、`k` 全不受影响），因此**带 ZOOM 与不带 ZOOM 的落点数据可直接比对** —— 这也是 §7.4「1920 不带 ZOOM」的数据能与其余五档并列的原因。
      ⇒ 反过来说：`dsf=2` 一直都在，所以「120 格只代表 DPR≈1」是**错的**；六档数据代表的是 **CSS 像素布局**（与 DPR 无关）。真正未覆盖的轴是**浏览器页面缩放（125%–200%）与系统字体缩放**，本轮没测。
    - **两个真 bug（仍挂着，未修）**：① `cdp.send()` **没有超时**，只有收到响应才 settle；② `ws` 的 `close`/`error` **只在连接阶段**有人处理，CDP 一旦断开，pending Promise **永不 settle** → 静默挂满 300 秒并产出空 dump。修完后同一次故障应在几秒内报「CDP 断连 / 请求超时，卡在 `Page.captureScreenshot`」。
