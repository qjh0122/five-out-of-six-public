## 二、疑点服务器侧计数证据（AC0，核心）

**方法**（避开上轮踩过的坑）：自建 Node `http` 静态服务 + 真 Edge + 真 SW，**只认服务器 handler 实际收到的 `/version.json` 请求**作网络出口，不采信 CDP `Network.requestWillBeSent`（SW 用 Cache API 应答也会发该事件）。SW 接管由 `navigator.serviceWorker.controller` 非空确认。判据自验 10/10 后才对实现下结论。
工具落盘 `tools/qa/version-endpoint-server-count.js`（可复用，退出码 0=三问全真），原始输出 `tmp/qa-version-endpoint-2026-11-20.json`。

### 2.1 三问证据表

| 问 | 实测方法 | 原始输出 | 期望 | 判定 |
|---|---|---|---|---|
| **① 温启动不静默跳过** | SW 接管后连续 4 次打开，服务器侧数 `/version.json` 条数 | controller=true；每次打开服务器命中增量 = **1 / 1 / 1 / 1**（累计 4） | 每次 1 条 | ✅ 成立 |
| **② 拿到最新值** | 内存把 `v` 改成 `20261120QA-MUTANT`（不动磁盘），在已接管页触发 `visibilitychange` | 页面 reload（loadSeq +1）；服务器在变异期收到 1 条，应答值 = `20261120QA-MUTANT`；anti-loop 稳定 | reload 且取到新值 | ✅ 成立 |
| **③ 负向无缓存条目** | 页内枚举 `caches.keys()` + 每个 cache 的 `keys()`；静态核对 PRECACHE 清单 | Cache API 中 `version.json` 条目 = **[]**；PRECACHE 含 `version.json` = false；磁盘 SHA 前后一致 | 零条目 | ✅ 成立 |

**判据自验**：10/10（路径分类 6：命中 `/version.json`、`/version.json?sharecode=…`，不命中 `/index.html`、`/js/game.js?v=…`、`/version.json.bak`、`/api/version.json`；版本比较 4：同版不 reload / 异版 reload / 空串不 reload / 非字符串不 reload）。含 3 命中 + 7 不命中样本。
**磁盘安全**：`version.json` SHA-256 `c864c435…51aa8` 变异前 = 变异后；全程只改服务器内存变量。

### 2.2 与实施日志 §四「transfer=0B」的交叉验证

独立复跑 `node scripts/probe-perf-once.js`（退出码 0）：

| 场景 | fetch transfer（我实测） | fetch **条数**（ResourceTiming） | SW Cache 条目数 |
|---|---:|---:|---:|
| firstVisit | 318 B | 1 | 67 |
| swWarm | 0 B | **1** | 102 |
| cpu4xWarm | 0 B | **1** | 102 |

关键：三个场景 `fetch` 条目数都是 **1**——SW 注入的 fetch 确实进了 ResourceTiming，只是 `transferSize` 记 0；而服务器侧计数证明这条请求真到了服务器（2.1 ①）。所以「transfer=0B」与「每次都向服务器发请求、拿最新值」**两件事同时为真**，实施日志 §四的解释成立，不是缺陷。
（注：`sw.js:334-337` 纯网络分支 `event.respondWith(fetch(req))` 与 Cache API 无条目相互印证；FCP/DCL 微小波动非本次口径，未做显著性判定。）

**AC0 三态结论：① 实测通过 / ② 实测通过 / ③ 实测通过。疑点不成立——实现正确。**
