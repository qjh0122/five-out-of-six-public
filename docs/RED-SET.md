# 能红集 · 三栏留痕操作手册

> 对应 `docs/REVIEW.md` §6.6 禁令三的 (b)。实现见 `scripts/check-red-set.js`，
> 数据见 `docs/red-set.json`（本轮记录）与 `docs/red-set.baseline.json`（上轮 id 快照）。
> CI 每一步 test job 跑两条命令：`npm run redset:selftest`（先证明尺子不瞎）+ `npm run redset:check`。

## 它守什么、不守什么

**守**：哪些断言被真实注入演示过「会红」，且这个「会红」此刻仍然成立。
**不守**：断言的正确性、覆盖率、因果关系——因果只能人判，机器只判得了「身份唯一」和「状态变过没变过」。

一句防误解的话：**能红集上升 = 被证明能红的断言数涨了，不是恒真项数降了。**
`ok(true)` 永远红不了，天然进不来；把 `ok(true)` 改成 `ok (true)` 只是加一个空格，骗不了这里的判据。

## 三栏留痕模板

每条记录分三栏，机器只碰第一栏、第三栏，第二栏由人写：

| 栏 | 字段 | 谁判 | 判什么 |
|---|---|---|---|
| **① 机器栏** | `assertion.file/line/name/hash`、`injection.file/line/expr_old/expr_new/hash`、`evidence.before/after` 的 `time/head/exit/assertion_result/output/fail_loc` | 机器 | 说明串文件内命中恰好 1；前后绿红字段自洽；红行对上断言；双端哈希未失效；本轮 id ⊇ 上轮 |
| **② 人判因果栏** | `causal` | 人 | 这次注入**为什么**让这条断言失败（写因果链，别只写「注入后红了」） |
| **③ 重验栏** | 失效后重跑的新 evidence + causal（覆盖原字段，`id` 不变） | 人执行、机器核 | 断言行或注入行一改，哈希即失效 → 必须同轮重验；重验过 ⇒ 恢复不算退化，重验不过 ⇒ 真退化红 |

## 新增一条（完整命令序列）

以种子记录 `deck-54-small-joker` 为例。每一步的输出都要原样留进 `evidence`，不要复述。

1. **选配对**：一个真实被测行为 + 守它的断言。先确认断言说明串在测试文件内**恰好命中 1 次**（含正文与代码块，命中 0 当「没定位到」）。
2. **前绿**：`node <测试文件>`，抓 `PASS  <文件:行>  <name>` 行。记 `time` / `head=git rev-parse HEAD` / `exit=0` / 原始 `output`。
3. **注入**：临时改被测源码（本例注释掉 `card.js:48` 的小王入堆行）。**保持行数不变**，否则 `文件:行` 会漂移，后端证据全废。
4. **后红**：再跑同一测试，抓 `FAIL  <文件:行>  <name>  -> <期望/实际>`。记 `exit!=0` / `fail_loc` / 原始 `output`。红线身份必须能对上注入点：若红的是别处，说明注入没打到目标，重做。
5. **还原 + 复原绿**：`git checkout -- <被改源码>`；再跑一次测试确认回到 `exit=0`。这一步不做，留下的注入会污染下一轮。
6. **算双端哈希**（口径与校验器一致，别手算）：
   ```
   node scripts/check-red-set.js --emit-hash <测试文件>:<行>
   node scripts/check-red-set.js --emit-hash <注入文件>:<行>
   ```
7. **写记录**：填进 `docs/red-set.json` 的 `records[]`；`causal` 写因果链（至少 20 字），并注明同源变红的旁证（旁证不是互证）。
8. **自检**：`npm run redset:check`（应全绿）+ `npm run redset:selftest`（7/7 判据能被红）。
9. **提交**：把当前 `records[].id` 固化进 `docs/red-set.baseline.json` 的 `ids`，保证下一轮的集合包含有参照。

## 重验一条失效记录

行内容一改，双端哈希即失效——这是**故意的**：否则断言被改弱后记录还亮着。正确处置不是删记录（那会触发「集合包含」红），而是：

1. 重新走上面的 2–6 步（同一 id，新哈希、新前后证据）；
2. 在 `causal` 末尾追加「因何失效、本轮何时重验、重验结果」；
3. `id` 保持不变 ⇒ 集合包含不退化；重验通过即恢复，不算退化。

## 已知边界

- `lineHash` 用 V8 的 `Error.captureStackTrace` 一致的文件行口径；去掉行尾 `\r`，CRLF/LF 通吃；换引擎要退回解析栈字符串（harness 同样的代价）。
- 本机制只管「被演示过会红」，**不保证**这些断言覆盖了线上真实故障分布——自己构造的样本永远在注意力分布内，分布内的错人肉会先抓住，所以门禁的失败仍可能被掩盖。这是「注入样本须来自真实数据」那条要求的来源，本机制不假装解决它。
