## 1. 测量契约（执行前必须先对齐，否则数字不可比）

这一节不是判据，是**断言能不能成立的前提**。任何一条没对齐，后面的数字都不具有跨轮次可比性。
规格 §6 Q0 已把①③④写进正文，本单在此基础上**把 (b) 与 §1.7 的争议点补完**。

### 1.1 被测节点

| 对象 | 选择器 | 说明 |
|---|---|---|
| 气泡外层 | `#emoji-layer > .emoji-fly` | 承载 `data-dir` / `--tail-off` / `--emo-k`（规格 §3） |
| 可见纸面 | 外层内唯一子元素 `.emoji-pop` | **所有 rect 断言一律量它** |
| 裁剪盒（= 视口边界） | `#emoji-layer` 的 rect | 真正会切掉气泡的那把剪刀 |
| 座位块 | `#game-top [data-pid]` | 含头像 + 昵称 + 分数，规格 §1 |
| 瞄准点 · 强 | 座位块内 `.opp-avatar` 的 **rect** | Q4a 用（v2.2 起是 rect 外扩，不是圆心距） |
| 瞄准点 · 弱 | 座位块 rect | Q4b 用 |
| 定位归因（可选） | 外层 `data-place ∈ {side, stack, fallback}` | **规格未强制要求**；缺它则 N8 / N12 的一半不可判（§7 K8） |

**为什么 rect 量内层而不是外层**：外层在短语档是 `width:auto`、表情档是 `64k` 方框，
两种档位里「玩家看到的边界」都是内层。量外层会在表情档多算/少算不可见留白。

**为什么视口用 `#emoji-layer` 的 rect 而不是 `innerWidth`**：`#emoji-layer` 是
`position:fixed; inset:0; overflow:hidden`。两者不等时（滚动条 / 移动端 URL 栏收起中）
以裁剪盒为准，并把 `innerWidth/innerHeight` 一并记进报告；差值 > 1 px 时标为环境异常，该格数据作废重跑。

### 1.2 座位编号（跨轮次 diff 用，不许每轮重排）

| 编号 | 定义 |
|---|---|
| S1 | 自己：`#game-top .gt-me[data-pid]` |
| S2~S5 | 对手：`#game-top .gt-opps [data-pid]` 按 DOM 顺序第 1~4 个 |

报告必须逐格记录 `S编号 → data-pid → 昵称 → 座位块 rect → 头像 rect`。
横屏 844×390 的顶栏是左右两栏布局（规格 §5），**座位枚举只准用 `#game-top [data-pid]`**，
不准用 `.gt-opps` 猜。

### 1.3 测量窗口（最容易出错的一条）

单条气泡生命周期：落定 `430ms`（`is-landed`）→ 回弹动画 `340ms` → `1500ms` 开始淡出并上浮 → `1900ms` 移除。

- **合法测量窗口：spawn 后 `[770, 1400] ms`**。下界 770 = 430 + 340；上界 1400 = 1500 − 100。
- **禁止**在 `0~770ms` 内量 rect：`emojiPop` 把内层放大到 `1.16` 倍（`pwa/css/emoji.css`
  的 `@keyframes emojiPop` 就是 `scale(1.16)`），高度/宽度偏大 16%，直接改掉
  「重叠面积」「gap」「可见字符」三组数字。
- 并发多气泡时新气泡会 `removeChild` 最老的一条（上限 6）。采样必须与生命周期错开：
  **一次只在一个窗口内采样一条，采样完立刻丢弃**。
- **量的是「最终落定态」，不是「首次规划态」**（v2.5 署名引入后新增的坑）：
  署名是内联前缀，会改变气泡高度 `h`，所以实现「加签名后重规划一次」。
  这意味着同一个气泡可能先落在一个位置、再挪到另一个位置 —— 我量的必须**是后者**。
  - 判断依据：G12③「`[770,1400]` 内同一节点 rect 变化 ≤ 1 px」。
    若重规划发生得晚（> 770ms），它**会表现成 G12③ 抖动红**，而不是「量错」——
    所以这条红不要往测量口径上解释，那是真的晚了；
  - 反面纪律：**不许为了提高命中率把窗口往后挪**。窗口是契约，挪了就与历史数据不可比。


### 1.4 节流

服务端 2 秒一条。合成发送间隔必须 **≥ 2100ms**，否则第二条被静默丢弃，
表现出来的样子是「这条座位没有气泡」→ 会被误诊成「方向选择把气泡弄丢了」。
（历史教训：`docs/PROBES.md` 里 v130 那次 `probe-emoji 0/2` 就是这类误诊。）

### 1.5 常量口径（避免「引用被测值」）

| 量 | 取值来源 | 允许读实现吗 |
|---|---|---|
| `gap` | 规格 §3：`10 × k`（短语）/ `4 × k`（表情）。**口径争议见 §11.3-c**，本单按 §2 的四条几何式判 | 否，写死 `10` / `4` |
| `MARGIN` | 规格 §3：`8`（不乘 k） | 否，写死 `8` |
| `TAIL_W / TAIL_H` | 规格 §3：`12 × k` / `8 × k`（`TAIL_H` 是**伸出长度**，进裁剪盒） | 否 |
| 尾巴夹取 `m` | 规格 §2 约束 C：`m = min(18 × k, L / 2)`（`L` = 贴合边长） | 否 |
| 上限宽 | 规格 §3：`min(460 × k, 100vw − 24)` | 否，写死 `460` / `24` |
| `k` | 规格 §3：`max(1, stageScale / 0.52)`，`stageScale` 读 `#stage` 的 `transform: matrix` | **否**，用 `0.52` 自算（`--emo-k` 只用于 G13 的**比对**，不作输入） |
| 气泡 `w/h` | 实测 `.emoji-pop` rect | 是（被测输出，作 oracle 的几何前提，不是结论） |

**`--tail-off` 的原点约定（本单强制）**：沿贴合边，**从该边的起点量到尾巴中心线**；
`left/right` 档起点 = 上边缘，`up/down` 档起点 = 左边缘。单位 = CSS px 数（可带 `px`）。
若施工方采用「距终点」「以中心为原点」，必须在复核前与本单对齐；
**不允许两套约定各算一套**——那样 G8 的数字毫无意义。

### 1.6 「内推优先 + 空间降序」的可复算定义（v2.2 新增，G4 的前提）

规格 §2 只写了「朝桌心的主轴方向」「可用空间 = 到最近障碍或视口边界的距离」。
落到断言上必须把三件事定死，否则 oracle 与实现各算一套，**G4 会整片假红**，
而那种红会被误记成「方向选择没生效」——这轮最贵的误诊就是这个形状。

**(a) 桌子中心 `C`** = 全部 `#game-top [data-pid]` 块 rect 中心的**算术平均**（5 块等权）。
不用「圆环几何中心」——那要读实现里的环半径，属被测值。

**(b) 内推方向 `inward`**：`dx = C.x − S.centerX`，`dy = C.y − S.centerY`；
`|dx| ≥ |dy|` → `dx > 0 ? right : left`，否则 `dy > 0 ? down : up`。
**`|dx| == |dy|` 归入水平支**（本单强制约定，规格未定）。
`tie` 出现次数必须报出来：某档 5 座里 ≥2 个 tie → 说明排布接近正菱形、排序信息量不足，
该档方向需人工复核一遍再判。

**(c) 可用空间 `cap(dir)`** = 从座位块在该方向的边缘，到最近**阻挡者**的距离：

- 座位块边沿：`right` 用 `S.right`、`left` 用 `S.left`、`up` 用 `S.top`、`down` 用 `S.bottom`；
- 预放位置的**横向跨度**（决定谁挡得住）：`left/right` 档 = `[Ac.y − h/2, Ac.y + h/2]`，
  `up/down` 档 = `[Ac.x − w/2, Ac.x + w/2]`（**不夹取**，用几何式原值）；
- 阻挡者 = ① 视口边界（`vw − 8` / `8` / `vh − 8` / `8`）；② 其他座位块 rect 中，
  横向跨度与上面那条**正重叠（`> 0`）**的块；
- `cap(dir) = min(阻挡者在该方向的坐标) − 座位块边沿坐标`，**允许为负**（= 已被挡住）；
- **排序**：`inward` 先试；其余三个按 `cap` 降序；`cap` 相等按 `right, left, up, down`
  固定顺序（保证 oracle 确定性，也让「tie 次数」成为一个可数指标）。

> **为什么不用「座位块中心沿射线测距」**：气泡是按**头像中心**对齐的，跨度不是座位块的跨度。
> 用座位块跨度会在「头像偏在块的一侧」时算出与实际可放宽度不符的容量，排序随之错位。

### 1.7 裁剪盒 = rect **单侧**外扩（G1 的前提，附可行性推导）

尾巴只在**朝座位的那一侧**伸出，所以裁剪盒是单侧外扩：

| `data-dir` | 尾巴所在边 | 外扩边 |
|---|---|---|
| `right`（气泡在座位右侧） | 气泡左边缘 | **左** |
| `left` | 右边缘 | **右** |
| `up`（气泡在座位上侧） | 下边缘 | **下** |
| `down` | 上边缘 | **上** |

**为什么必须单侧（独立复算，不改这条那 10 格永远修不绿）**：

- `vw = 320` → 气泡上限宽 `= vw − 24 = 296`，两侧余量 `= 24 / 2 = 12`；
  四边外扩要求每侧留 `MARGIN 8 + TAIL_H 8 = 16 > 12` → **差 4px×2，必然越界**。
- `vw = 390` → 上限宽 `366`，两侧余量同样 `12`，同一个算式，同样越界。
- 而 T2（17 字）**一定顶到上限宽**：`17 × 24 × 1 + 18 × 2 = 444 > 296 / 366`
  → 折行并把宽度撑到 cap。所以四边外扩口径下 `320×T2`、`390×T2` 共 10 格**全红且不可能修好**。
- 单侧外扩恰好可行：`left = 8 + 8 = 16`、`right = 312`，宽 `296` → **零余量**（详见 §4.4）。

> 这是本单对规格 §6 Q1 的**必要修正**，见 §11.2 第 8 项。

### 1.8 尾巴尖端 `tip` 的统一算法（G2 / G6 / G7 共用，本单定义）

```
T = TAIL_H × k   （= 8k，伸出长度，进裁剪盒；TAIL_W 只影响三角底宽，不进尖端坐标）
tip = dir=right : (r.left  − T,  r.top    + tailOff)
      dir=left  : (r.right + T,  r.top    + tailOff)
      dir=up    : (r.left  + tailOff, r.bottom + T)
      dir=down  : (r.left  + tailOff, r.top    − T)
```
`tailOff` 取 `--tail-off` 的解析值（按 §1.5 原点约定）。**三个判据共用一个 `tip`，
不许各写一套公式**——两套公式意味着两个「尾巴」，报告里说不清哪个是真尾巴。

`T = 8k`；`tip` 见 §1.8；`m = min(18k, L/2)`。

| **G16** | **兜底必须署名（Q10，v2.5 新增）** | `.emoji-by` 的 `textContent` + `state.room.players[ev.from].name`（独立 oracle） | **两条定级 + 一条前置**，见 §2.3。① 数量口径：`set(兜底气泡) == set(带署名气泡)`，**集合相等不是数量相等**；② 内容口径：逐条 `norm(byText) == norm(players[from].name)`，覆盖率 **100%**，一条不符即红；③ 前置（只 WARN 不定级）：样本内 ≥2 个不同发送者且昵称互不相同 | 规格 §6 Q10 + §4.3。「覆盖率 100%」这个写法**单独用会被一行硬编码骗过**（`昵称 = '对方'` 也能 100%），所以必须补 ② 的内容比对，见 §2.3 |

### 2.1 G15 / Q8 判定表（v2.6 改口径：一个数拆成三个数）

v2.5 加了署名之后，「不指人」不再是单一危害。**v2.6 把预算拆开**（规格 §4.2）：

| 档位 | 分母（格） | ① 定向落点 | ② 不指人但**已署名**（观察，不阻断） | ③ 不指人且**未署名**（阻断） |
|---|---|---|---|---|
| 320×568 | 20 | 记录 | **≤ 8** | **≤ 2** |
| 390×844 | 20 | 记录 | **≤ 8** | **≤ 2** |
| 844×390 | 20 | 记录 | **≤ 8** | **≤ 2** |
| 1366×768 | 20 | 记录 | **≤ 8** | **≤ 2** |
| 800×600 | 20 | 记录 | **≤ 8** | **≤ 2** |
| 1920×1080 | 20 | 记录 | **≤ 8** | **≤ 2** |

**G15 通过条件（四条全满，缺一条即不通过）**：

1. ③ ≤ 2；② ≤ 8；且**三个数都要打印**（`定向 / 已署名 / 未署名`），只报合计数算未测；
2. **三数之和必须严格等于分母**：`① + ② + ③ == 20`。**不等即判「该档未测」**，
   不是「差 1 算容差」—— 和不对说明探针把某条气泡漏计或重计了（例如没有 `.emoji-by` 元素的气泡被丢出统计），
   这种情况下 ③ 的小数很可能正是漏掉的那几条，越绿越假；
3. ② 超 8 条 → **该档不得判「通过」，最高只能「有条件通过」**，且必须写进发布说明。
   ⚠️ 这条是 v2.6 口径带出来的新假绿：② 是「不阻断」的观察项，若不把它接到出口判定上，
   **「20 条全兜底 + 20 条全署名」会得到 ③=0 的满分**，而真实情况是一条都没指到人。
   规格给的 `≤ 8` 就是唯一的地板 —— 定向落点因此天然 `≥ 12/20（60%）`。
   **不要另外发明一个「定向率」阈值**（没有任何独立来源支持某个百分比），把 `≤ 8` 用足即可；
4. **（本单加固）** 320 档的 ③ 不得全部来自 T4 定向格；出现「T4 占满预算」时转「观察通过」，
   需补 1 帧人工复核并在报告标注（理由见 §9.5：Q4a 80% 与 Q8 预算两层宽松叠加会同时满足而视觉很糟）。

**③ 与 G16 必须同源同次（不许跨次拼）**：③ 的定义就是「Q4b 失败 **且** 无署名」，
它正是 G16a（`set(兜底) == set(署名)`）的补集。两处若取自不同次跑，
会出现「③=0」与「署名覆盖率 100%」互相印证的假绿 —— 两边都因为同一个漏计而变绿。
**规格 §4.2 要求的三个数，必须由同一次跑、同一批 DOM 快照算出。**

**Q4a 的分母（歧义已记录，不静默）**：规格 §6 Q4a 只写「定向落点中 ≥ 80%」，
没定义分母是 T4 的 5 格还是全部 20 格。本单判定用 **T4 的 5 格（≥ 4/5）**，
并**强制探针同时打印全部 20 格的 `n/20`** 作为观察值。若规格方本意为全部 20 格，
阈值换算为 `≥ 16/20`，判定随之改 —— 两个数字都出现在报告里，歧义就不会变成静默的判定差异（§11.3-b）。

### 2.2 G16 / Q10 的可执行拆解（v2.5 新增，v2.6 后成为唯一归属保障）

规格 Q10 写的是「署名覆盖率 = 100%」。**这个阈值单独用会被一行硬编码骗过**：

| 实现写法 | 覆盖率 | 实际归属 | 只查覆盖率会判 |
|---|---|---|---|
| 写死 `昵称 = '对方'` | 100% | 完全不知道谁发的 | 绿（错） |
| 写死 `昵称 = 第一个对手名` | 100% | 5 个人全显示同一个名字 | 绿（错） |
| 正确实现 | 100% | 正确 | 绿 |

所以 G16 拆成「两条定级 + 一条前置 + 一条 oracle 边界」：

| 代号 | 口径 | 断言 | 定级 |
|---|---|---|---|
| G16a | 数量 | `兜底 ⊆ 署名`：每条 Q4b 失败的气泡必须有署名，**逐条比对**（不是数量相等）。反向 `署名 ⊆ 兜底` **只 WARN** | **缺一条即阻断**（兜底未署名 = 用户不知道谁发的）。**「多」不阻断** —— 规格只要求兜底必须有、没禁止别处有 |
| G16b | 内容 | **三层链**：`norm(byText)` == `norm(fromName)`（dump 每行带的页面真实昵称，主判据）；`fromName` 与 fixture `players[from]` 不一致时记 **oracle 漂移**（只 WARN，不判产品红）。`norm` = `trim` + 去尾部 `:`/`：`/空白 | 一条不符即**严重**；署名撞到另一个座位的名字记「**串座**」，升**阻断** |
| G16b' | 可见 | `by.scrollWidth ≤ by.clientWidth + 1`。**必须用只表达署名自身的字段 `byOwnTruncated`**；若探针只给 `byTruncated`（= 署名被裁 **或** 整气泡被裁，`\|\| clipped`），缺陷归属不明，报告须写「署名或气泡被裁」 | 署名被裁 = 等于没署名 → **严重**。**不许把气泡的 G10 缺陷写到署名头上**（误归因） |
| G16c | 前置 | 样本内 ≥2 个不同 `from`，且 `players` 里这些昵称**互不相同** | 不满足只 **WARN**：该档 Q10 只能证明「有名字」，不能证明「归属唯一」，报告须写明 |
| G16d | **oracle 边界** | `players` 里**没有**该 `from` 时，我没有真值 → 本条记「**未测**」，既不判绿也不判红。用 `--complete` 声明「这份 players 齐全」后，缺键才按规格判（应写「对方」） | 「未测」>0 时**该档最高「有条件通过」**。**未测不许占全绿的位置** —— 这是最容易把自己洗成通过的地方 |

**为什么 Q10 要三层链（byText ↔ fromName ↔ fixture），不能只用一个**：

| 只用 | 会漏什么 |
|---|---|
| 只用 `byText` vs fixture | 漏「座位显示的名字与署名不一致」——座位上写「陪练2」、气泡上写「阿宝」，两边都错得很一致，用户认不出是谁 |
| 只用 `byText` vs `fromName` | 漏「数据本身就错」——两者最终都源自 `players[].nickname`，**同一个源一起错就一起绿** |
| 三层齐上 | `byText`↔`fromName` 抓「用户看到的两处名字不一致」；`fromName`↔fixture 抓「夹具/数据漂移」。**漂移只 WARN**，那是尺子与夹具的问题，不是产品缺陷 |

→ 已落成 2 条自验样本：⑩「署名与 fixture 一致但与 `fromName` 不一致 → 必须红」（证明 `fromName` 真在判）、
⑪「`fromName` ≠ fixture、署名 == `fromName` → 只 WARN 不判红」（证明漂移不被当成产品缺陷）。

**为什么 G16d 不是「判红」也不是「判绿」**：`players` 缺该座位名时，实现写「对方」（合规）或写别的名字
（可能读了别处的名字）**都讲得通**。这时候判红是误伤、判绿是放水，唯一诚实的动作是记「未测」。
配套纪律：**未测要往出口传导**（降为有条件通过），否则一堆未测照样能凑出一个「通过」。
现状：`tools/qa/players-fixture.json` 里 5 座昵称齐全（`me → 我`，4 个陪练 `陪练/陪练2/陪练3/陪练4`），
其中 `me` 是**夹具常量**（team-lead 裁定起局时显式写死），与产品取名逻辑无关 —— 否则就成了「引用被测值」。

**署名到底在哪些气泡上（已核代码，不是推测；上一版我误写成「一律署名」，此处已纠正）**：

触发条件是 `if (!spot.reach)`（`seatSheetView.js:994`）= **Q4b 不成立才署名**，不是无条件。
加完署名会因尺寸变化重算一次落点（`planSpot(...) || fallbackSpot(...)`），**只重算一次、不迭代**（防循环）。
由此产生**一小撮**「重算之后其实指得到了、但署名已经加上去了」的气泡 —— 这是唯一的「多署名」来源。

| 情况 | 实际情况 | 本单判定 |
|---|---|---|
| 兜底气泡有署名 | 正常 | G16a 正向通过 |
| 兜底气泡**没**署名 | 功能失效：用户不知道谁发的 | **阻断**（N14） |
| 重算后指得到、但署名已在 | **合规**（署名与尾巴同时成立只是更清楚） | **只 WARN**，按下列分档处置（阈值**先登记后用**） |
| **非兜底格大面积带署名** | 不是署名逻辑问题，是 **`reach` 判定位置有问题** | **单独报给施工方诊断**，不作为署名缺陷计 |

**「重算副作用」条数的分档（team-lead 2026-11-14 拍定，先于实测登记）**：
先定数再用，是为了防「看到结果再定阈值」—— 那种阈值永远刚好卡在实测值上方。已写进
`tools/qa/emoji-verdict.js` 的 `[G16a^]` 检查，机械判定，不看人。

| 条数/档 | 判定 | 报告处置 |
|---|---|---|
| **≤ 2** | 正常副作用 | 不单列 |
| **3 ~ 9** | 正常副作用，但量偏大 | **单列**「重算副作用 n 条」 |
| **≥ 10** | **不叫副作用了** → 报「`reach` 判定位置可疑」，请施工方单独查 | 该档降**「有条件通过」**（**本单定级**：可疑项不落通过；若团队认为过严可改回纯告警，但要写明） |

**因此 `未署名` 与 `覆盖率` 仍然是有效分类项**（我上一版推的「恒为 0 / 恒 100%」是错的，那个前提是「所有气泡都署名」，
而代码不是这样）。`已署名 ≤ 8` 依旧只是观察项那道闸，主闸是 `未署名 ≤ 2` + G16b 逐条内容比对。

**一个必须提前说的假红（G10 × 署名）**：短语的署名是 `insertBefore(by, item.firstChild)` ——
它被插进了**正文容器内部**，所以那个容器的 `textContent` 从此包含「昵称：」。
`textContent.length === 原文.length` 这条断言（G10①）会因此**每格都红**。
所以：
- **正文可见字符数必须排除 `.emoji-by`**（按单个字符 `Range` 量，且跳过署名节点的字符）；
- dump 必须分别给 `bodyOriginal`（原文）与 `bodyVisibleChars`（不含署名），**不许只给一个总长度**；
- 这条属于「尺子会假红」的典型：不改判据，改测量对象。




`norm` 为何要去尾部冒号：规格写「正文前加前缀 `昵称：`」，但**冒号在不在 `.emoji-by` 里没规定**
（可能在元素内，也可能作为正文首字）。不归一化会造出一条与实现无关的红 —— 那是尺子的错，不是实现的错。

**⚠️ 我自己的判据被自己推翻一次（记录，防下轮重犯）**：
初稿我加了第三条 FAIL「不同发送者署名全同 → 判硬编码」。写自验样本 ⑦ 时发现那是**误伤**：
两名玩家真叫同一个昵称时，实现照 `players` 抄名字是**正确的**，判红等于拿数据撞名去怪实现。
而「硬编码一个人名」这种假绿，G16b 的逐条比对已经挡死（自验样本 ②）。
→ 按验收判据第 2 条「误伤评估」：**该 FAIL 作废，降级为 G16c 前置检查（只 WARN）**。
判据四条连我自己新写的判据也照砍，这是它存在的意义。

**视觉子项（只到建议级，每条都写清为什么不能再严）**：
- 短语署名字号比 `fontSize(.emoji-by) / fontSize(正文) ∈ [0.72, 0.88]`（规格 0.8×）→ 可断言，抽 3 格；
- 短语署名不透明度 ≈ 0.7：`opacity` 与 `color` 的 alpha **两种取法都认** → 只**建议级**，
  理由是实现可能走 `opacity` / `rgba` / `color-mix`，写死一种会误伤；
- 表情署名「图片下方一行、`0.7 × 基准字号`」→ **不可自动判定**：`基准字号`没有独立来源，
  读实现的基准值就违反「不引用被测常量」→ 归入 §7 目检项（K10），不进自动判据。

**Q10 与 G10（不截断）的耦合 —— 必须一起测，不许分开报**：
署名是**内联前缀**，占的是正文那一行的横向空间。320 档气泡上限宽 `= 320 − 24 = 296`，
长短语加 3~5 字前缀后行数只会变多不会变少 → `h` 变大 → 需要的竖直净空 `gap + h` 变大 → **更多兜底**。
所以：
1. G10 改成「**正文**可见字符数 == 原文长度 **且** 署名未被裁」，不能只数总字符数；
2. **Q8 的旧数字一律作废重测** —— §13.5 那张表是**署名实现之前**跑的。
   320 档旧值 `3/20` 已顶到旧上限，署名一旦把 `h` 抬起来就会变 —— 必须重跑，不许沿用。


### 2.3 判定原则

- G1~G13 **逐格判定**（**120 格**，六档全跑，无抽样），不打平均分；任一格红即该格红。
- G15 **按档判定**（**6 个** 20 格全覆盖档，K9 已关闭）。
- G14 是**整轮门禁**，不通过则以上任何绿都不得作为交付依据。
- **兜底档**（四向全废 → §4.1 兜底链）：方向不参与 G4/N1（§7 K4），但 G1/G2/G7/**G16** 必须判。

### 2.4 区间搜索（v2.6 §4.1）对 G5 的影响：**我不同意「gap 要开豁免」**

team-lead 的裁定是「发生位移时 gap 不再精确，改为判『位移量 ≤ 尾巴可补偿幅度』且 `gap ≥ gap_min(2k)`」。
**方向我同意，但我算了一遍：位移不会改变 gap。** 理由是一行几何：

- 规格 §4.1 规定 `up/down` **在 x 上**搜索、`left/right` **在 y 上**搜索 —— 即位移轴**平行于**块的那条边；
- 而 `gap` 量的是**垂直于**这条边的距离：`down` 时 `gap = r.top − S.bottom`，只与 y 有关，x 怎么滑都不变；
  `right` 时 `gap = r.left − S.right`，只与 x 有关，y 怎么滑都不变。四条方向同理。
- → **`gap` 在区间搜索下仍然精确等于 `10k`（表情 `4k`）**，G5 的第一项不需要豁免。

**真正被区间搜索打破的是 G5 的第二项「头像中心对齐」**：`|r.centerY − Ac.y| ≤ 1`（上下档 `centerX / Ac.x`）。
滑动就是让对齐偏离，所以**这条才要豁免**。改法：

| 条件 | G5 判定 |
|---|---|
| `place == 'dir'` 且 `shift == 0` | 原样全判：`gap` 精确 `±1` **且** 中心对齐 `±1` |
| `place == 'dir'` 且 `shift ≠ 0` | `gap` 精确 `±1` **照旧判**；中心对齐改为：① `|shift| ≤` 头像**沿位移轴的跨度的一半**（= 尖端仍落在头像跨度内，与 Q4a 轴线①同义）；② `tip` 仍须满足 G7；③ 位移量由探针输出，`shift` 字段缺失则该格**判未测** |
| `place == 'stack'` / `'fallback'` | 不判 `gap` 与对齐，只判 G1/G2/G7/G16 |

**为什么不能像裁定那样给 gap 开口子（误伤评估）**：
`gap ≥ 2k` 这个下界等于允许气泡贴到离块 2px。一旦开了这个口，**施工方可以关掉区间搜索、
改成「把气泡往块上怼」来同时过 A 和 B**，而 G5 依然绿 —— 那正是 team-lead 自己担心的
「为了过 G5 把搜索关掉」的镜像版本。反过来，坚持 `gap == 10k` 精确，
**搜索只能沿平行轴滑**，滑不出「贴脸」也不会滑到「离块太远」，两个坏方向都被堵住。
**这不是提高门槛，是这条豁免根本不需要**：`gap` 本来就没变。

**要新增的探针字段（没有它本节不可执行）**：`place`（`dir`/`self`/`stack`/`fallback`）+ `shift`（带符号位移量，px）。
这两个字段必须逐格打印。现有探针不输出 `shift`，所以本节在探针补字段前**只能判 `shift == 0` 的格**，
其余格如实标「未测」，不许按「大概没滑」放行。

**裁定结果（v2.7 §14，已定，不再讨论）**：规格方原拟「`gap ≥ 2k` 开豁免」，本单提出反驳后**整条撤回**，
改为按本节的写法落地 —— `gap == 10k` 精确照旧、只豁免对齐、新增 N18（`shift` 字段缺失本身计 1）。
规格 §14 同时把反驳理由（「往块上怼」是「关掉搜索」的镜像捷径）写进去，防止以后再开这个口子。
**注意**：这意味着 **`shift` 字段是硬需求，不是 nice-to-have** —— 没有它，带位移的格永远只能记「未测」。

## 3. 负向断言（18 条，全部要求计数 == 0）

### 3.1 关于「方向规律性」这类断言的两次修订（记录判断过程，不要只看结论）

**第一次（v2 阶段）**：规格 §6 初版 Q6 写「同一锚点同一方向连续出现次数超过 1」。
本单**不按字面执行**，理由（误伤评估）：同一座位 + 同一方向 + 不同内容类型
（S5 的 17 字长短语和 64×64 表情都挂右侧）是**完全正常**的结果，
按字面判会把正确实现判红 —— 判据一旦误伤，就会逼着实现去做不该做的事。
当时替换为「N2 = 同档 5 座 `data-dir` 全同但 oracle 非全同」。

**第二次（v2.2 阶段，本轮）**：`N2` 这个替换**也过期了**。
规格 v2.2 改成「内推优先」后，同一档里出现**规律性反向**是**期望行为**
（左半桌内推朝右 → `right`，右半桌内推朝左 → `left`）。
继续用任何「同档方向应一致 / 不应反向」类断言，都会把正确实现判红。
**现 N2 改为「内推可用却未选内推」，逐格计数。**

**这条记录本身就是一条验收纪律**：规格变更与实现缺陷在报告里长得一模一样
（都是「期望方向 ≠ 实际方向」）。唯一的拆法是**先按新规格复算期望值，再比实测**，
而不是拿上一轮的期望值当基准。这也是本单要求 oracle 独立成文件的原因 ——
规格改了，改的是 oracle 一处，不是散落在 15 条断言里。

### 3.2 N18 的效力边界 + `shift` 字段的轴向不统一（v2.7 补，不夸大自己的判据）

**① N18 抓不到什么（必须写下来，否则会有人以为它覆盖了规划逻辑）。**
被测实现在**规划期**已经用同一条几何拦过一遍：
`seatSheetView.js:776` `if (Math.abs((vert ? spot.tip.y : spot.tip.x) - acAlong) > acHalf + 0.5) continue;`
—— 也就是说「规划时直接选了个会撒谎的位移」这件事，N18 永远看不到（进不了 DOM）。
N18 真正覆盖的是**落定态**三件事：
- **(a)** 换行让位分支写出来的 `shift` 与实际位移不符（见下 ②）；
- **(b)** `--tail-off` 补偿算错（`shift` 变了但 `tail` 没跟上）；
- **(c)** `data-dir` 与 `--tail-off` 写入顺序错 → 首帧跳向默认方向（`seatSheetView.js:1019-1027` 注释自称已避开，**这条只能靠 N11 抖动 + 录屏兜**）。

**结论**：N18 绿灯 ≈「落定态没有二次失真」，**不等于**「位移策略正确」。位移策略的正确性靠 §2.4（gap/对齐）与 N8（让位前置合法）承担，不要都压在 N18 上。

**② `shift` 一个字段两种语义 + 两轴混算（测量字段问题，级别：一般；实现侧 18:39 已修）。**

| 位置 | **修前**（我 18:29 读到的那版，也是我报给实现侧的那版） | **修后**（18:39，已核对源码） |
|---|---|---|
| `shiftSearch`（原 `:779` → 现 `:783`） | `spot.shift = Math.round((vert ? spot.left : spot.top) - basePos)` —— **拿 x 减 y**，两轴混算，量出 215 / 275 这种假数 | `spot.shift = Math.round((vert ? spot.top : spot.left) - basePos)` ✓ 实测位移 |
| `runPass` 换行让位（原 `:798` → 现 `:806`） | `spot.shift = away * r * (h + SHIFT_GAP)` —— **候选**偏移，`judge` 夹取后 ≠ 实际 | `if (spot) { spot.shift = Math.round(spot.top - base.top); return spot; }` ✓ 实测 |

**一个字段两种语义 + 两轴混算**，两处都改了。影响评估与处置：
- 我的 N18 **不消费 `|shift|`**（只用它判「有没有测过」），所以**从未据此判过任何实现缺陷**；
- 但**我自己拿这个脏数当过「误伤量化证据」**，见 ③ —— 那是我的漏，不是实现的问题；
- 处置：**不计为产品缺陷**，按实现侧已修的状态记账，并在工具里补了「量级上界自检」（③），
  让这一类「字段悄悄算错」下次能被一条必要条件抓住，而不是靠人眼觉得数大。

**③ 这节的量化证据我撤回了一次，过程必须留档。**

我原本写的是：390 dump 上按 `|shift| ≤ avHalf` 判 **13/20 违例**、按 `|tip − faceC| ≤ avHalf+0.5` 判 **0/20**，
用「13 vs 0」当「两者不能互换」的硬数。

**这两个数后来全部作废**：`shift` 当时是**跨轴相减**写出来的（`(vert ? spot.left : spot.top) - basePos`，
拿 x 减 y），215 / 275 这种「看上去位移严重超预算」的值**根本不是位移**。实现侧 18:39 已修（见 §13.14）。

**我错在哪（写下来免得重犯）**：我只核了「尖端对准」这一头（偏移 `0.0`），
**没核「275 这个量级本身可不可能」** —— 而 `seatSheetView.js:727` 的注释就写着位移上界
`|位移| ≤ (跨度/2 − m) + 头像半跨`。一个 366px 宽的长短语，上界也就 197；275 早就越界了。
**判据四条里的第 4 条（上限要用极值跑一遍证明可达）就是干这个的，我这次漏了。**

**补上的办法（已落盘进 `emoji-n18-ruler-compare.js`）**：不依赖 `k`、不依赖被测常量的**必要条件**
`|shift| ≤ 气泡沿位移轴跨度/2 + 头像跨度/2`（因为 `m ≥ 0`，所以它一定是 `:727` 那条的必要条件）。

| 对照 | 结果 |
|---|---|
| 阳性（带跨轴 bug 的旧 390 dump） | **超界 5/16**，最重一条 `长短语@…/down shift=275 上界=197.5` |
| 阴性（修好后的 320 dump） | **超界 0/17**，`max|shift|=124` / `max 上界=156.5` |
| 自验 | `selftest 10/10` + `rangeSelftest 3/3`（含「跨轴特征必须命中」「正常微调必须不命中」「缺 rect 记未测」） |

**并且这一条我当场砍掉了一个自己的判据**：原本还写了「`max|shift| > 4×头像半跨` → 疑似跨轴」，
在修好后的 320 上**当场误报**（长短语 legit 位移 124，而 `4×8=32`）——
位移上界由**气泡跨度**决定，不由头像决定，**拿头像当分母就是错的分母**。砍掉，只留硬上界。
**硬上界是必要条件，抓得住跨轴这类粗错，抓不住量级接近的小错，所以它不替代 N18。**

### 4.4 临界格（零余量，必须单列）

## 5. 独立复算与工具自验

### 5.1 oracle：方向（两级排序）与尾巴偏移的独立实现

判据 G4 / G5 / G8 的期望值来自**独立实现**（`tools/qa/emoji-placement-oracle.js`），
不允许调用被测的 `planSpot` / `playEmoji`，也不复用其常量或 `DIRS` 数组。输入只有几何：

```
输入：seatRects[5], avatarRects[5], w, h, vw, vh, gap(=10k|4k), MARGIN=8, TAIL_H=8k
输出：{ dir, tailOff, order[4], 每向的否决理由 cap/A/B/D }

# 1) 排序（§1.6）
C = 5 个 seatRect 中心的算术平均
inward = snap(C - S.center)                    # |dx|>=|dy| → 水平；相等归水平
order  = [inward] + sort(其余3向, by cap desc, tie→right,left,up,down)

# 2) 四向几何（规格 §2，不夹取）
place(right): left = S.right + gap;        top = Ac.y - h/2
place(left) : left = S.left - gap - w;     top = Ac.y - h/2
place(up)   : top  = S.top - gap - h;      left = Ac.x - w/2
place(down) : top  = S.bottom + gap;       left = Ac.x - w/2

# 3) 约束（v2.2：C 不参与否决，理由见 §11.3-a）
A: 单侧重尾外扩后仍在 [8, vw-8]×[8, vh-8]（§1.7）
B: 短语 → 全部 seatRect 交集为 0；表情 → 仅非锚点 seatRect 需为 0
D: 与存活气泡 rect 交集为 0

expected = order 中第一个满足 A && B && D 的 dir
tailOff  = clamp(Ac_along - pos_along_start, m, L - m)   # m = min(18k, L/2)
```

**四向全不可用**时走规格 §4.1 兜底链 / 换行让位 —— 这一支只有「A 必须成立 + Q4b 计入预算」
可判，「具体落在哪」不判（§7 K4）。报告必须标 `兜底档 / 换行档，方向不参与 G4·N1`。

## 8. 真人路径（硬性，缺此项则整轮不算通过）

几何矩阵可以用 `RoomStore.sendEmoji(roomId, fromId, to, id)` 合成（公开 API，
走的仍是 `onEmoji → playEmoji` 同一条路径，不是注入式调试钩子），**但这不算真人路径**。

必须另有一条：

1. 关掉一切，从**浏览器地址栏**打开，不点文件、不看 README、不用任何调试钩子、不加 `?dev=1`；
2. 正常建房 → 加满 5 座 → 开局；
3. 点表情按钮 → 面板 → 发一条**长短语**给全场；
4. 再点某个对手座位 → 定向发一条**表情**；
5. 走到第一个决策点（发完这两条、观察气泡落点与消失）结束。

**记录要求**：录屏或连续 3 帧（发出 → 落定 → 消失），并写清「是否一眼看出归属」。
**注意**：历史上出现过「24 项浏览器验收全过，但全部通过调试钩子主动调 API —— 玩家没有那个钩子」，
所以「矩阵 120 格全绿」与「玩家能玩」之间没有必然关系，两者必须都做。

### 13.1 D1（阻断）Q8 在 390 档结构性不可满足

- 实测 **6/20**（预算 ≤2），其中长短语 5 格里 **4 格走兜底**。

**v2.4 允许夹取之后仍未解（QA 复核，结论比数字重要）**：

| 座位 | 实际落点 | 尖端 | 判定 |

**但这不构成「结构性不可满足」，证据如下（可独立复算）**：
以 pal 为例，它「本该」落在的 down 位置是
`left = clamp(Ac.x − 183, 8, 16) = clamp(−123, 8, 16) = 8`，`top = S.bottom + 10 = 98 + 10 = 108`：

| 约束 | 代入 | 结果 |
|---|---|---|
| A（单侧尾在顶边） | `left 8 ≥ 8`、`top−8 = 100 ≥ 8`、`right 374 ≤ 382`、`bottom 190 ≤ 836` | **成立** |
| C / Q4b | `tail = clamp(60−8, 18, 348) = 52` → `tip = (60, 100)`；块底 98 → 距 2 ≤ `gap+T = 18` | **成立，且尾巴对准头像中心** |
| B | 需 `x∈[8,374] × y∈[108,190]` 与某个座位块相交才失败 | **未定** ← 唯一缺口 |

⇒ **结论是一个二分，而不是「无解」**：

1. 若 108–190 带内**没有**座位块 → B 也成立 → 该走 `down(dir)`，
   **这是实现漏了分支（夹取只在部分路径生效），记实现缺陷**；
2. 若带内**有**块（例如第 5 座落在中段）→ B 翻不过去，**这才是结构性不可满足**，

上面二分立刻收敛——不需要再猜，也不需要再跑一轮全量。

### 13.2 D2（阻断）Q4a 在 `down` 落点上结构性不可达

|---|---|---|

### 13.14 `shift` 跨轴相减的 bug（实现侧 18:39 修）与我这轮的取证漏项

**事实**：`shiftSearch` 原写 `(vert ? spot.left : spot.top) - basePos`。
`vert` 的含义是「位移轴竖直」（`right`/`left` 这类侧边放置：y 在动、x 被 `gap` 钉死），
所以竖直时该取 `spot.top`。原式**拿 x 减 y**，出来的是视口尺寸量级的数
（320 档见 215、390 档见 275），**不是位移**。已改为 `(vert ? spot.top : spot.left) - basePos`（现 `:783`）。
同批修的第二处：换行让位原写**候选**偏移 `away * r * (h + SHIFT_GAP)`，改为实测 `spot.top - base.top`（现 `:806`）。
→ 我在 §3.2② 报的「一个字段两种语义」**成立且已修**。

**归属/表述更正（这条重要，别让后人读错历史）**：实现侧注释写「QA 据此判『位移超界』」——**不准确**。
我**从未用 `|shift|` 判过任何实现缺陷**（N18 从第一版起就判 `tip` vs `face`，拒绝用 `shift`）。
我的错是**另一件事**：在反驳「拿 `shift` 当判据」时，**引用了这个脏数的量级当误伤证据，却没先做量级合理性检查**。
两件事必须分开记，否则以后会有人得出「因为字段写错了，所以 N18 判据也错了」——**判据没错，我的证据链错了。**

**我本可以更早发现**：`seatSheetView.js:727` 自己就写了位移上界
`|位移| ≤ (跨度/2 − m) + 头像半跨`。390 那条长短语跨度 366 → 上界 197，而 `shift = 275` **早就越界了**。

**硬上界**检查 `|shift| ≤ 气泡沿位移轴跨度/2 + 头像跨度/2`（必要条件，不依赖 `k`、不引用被测常量）：

   - **为什么不加判据**（我提的「尾巴到非发送者座位距离 > 阈值」被主程驳掉，我接受）：给一个**本来就不该有方向的元素**定方向，判据会越写越绕，成本大于收益。
   - **但它是真问题**，而且不只是「未覆盖」：署名说「我说的」、尾巴说「对陪练4说的」，**两个矛盾的归因信号**，而用户会按尾巴理解。
     更要紧的是 **规格自己写了「尾巴指向空气」**（`:205`）—— 这句与实测不符，已记 **D9**。标尺写错，比实现错更难查，因为没人会去验标尺。
   - **改法（已落地，不在发布后）**：team-lead 判成缺陷并直接改掉 —— `place = fallback` 时**不画尾巴**（`data-tail="off"`），只留署名。
     我原本只判「设计代价 + 文档不一致」，**他比我狠一档，而且他是对的**：我把「指错人」当成了可接受代价。
     但这一改动**动了几何**（尾巴参与 Q1 裁剪盒外扩、Q4b 尖端判定），所以必须重跑六档 —— 而且**尺子得先换**，否则重跑出来的绿是「旧尺子量新东西」（D11）。

**同时声明覆盖到哪**：六档里**看过五档**（320 / 390 / 844×390 / 1366 / 800×600），缺 `1920×1080` 那套。
其中「四方向齐全」由 `800×600` 与 `1366×768` 两张支撑（其余档有的一屏只出一种方向）。
仍然：**这不是「六档都看过」，是「五档看过、最大屏没看」** —— 缺的那一档请补看，或缺就说缺。

### 14.7 结论

**整轮 = 有条件通过（1 个阻断条件 + 1 个收口条件）**
